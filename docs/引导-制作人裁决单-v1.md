## 二、追加裁决（规格未明确或互相留白）

| # | 项 | **终裁** |
|---|---|---|
| **C-6** | 视觉规格 5.2「新增文件 0」 | 指 **`assets/` 目录零新增**，不是全仓零新增。允许新增 `js/guide.js`（独立模块，避免污染 `ui.js` 的渲染缓存）与 `tools/guide-smoke.cjs`。`assets/style.css` 仍只追加段落、不改任何既有规则。零外部资源 / 零新依赖不变。 |
| **C-7** | `?guide=1` 语义 | 视为**强制复跑 + replay 语义**：自动进入第 1 夜并从 G1 起播，**全程不改写标记**（完成/跳过都不写），保证 QA 可无限重放且不污染真实用户状态。`?guide=0` 抑制自动触发。无参数的真实首次路径仍按 3.2 写 `done`/`skipped`。 |
| **C-8** | 锚点可见性判据 | **不采用** `offsetParent !== null`（该写法见设计案 §四-④ 的否决段）：≤760px 时 `.action-dock` 是 `position:fixed`，其 `offsetParent` 恒为 `null`，会把 G3/G4 锚点误判为不可见。改用 `display!=='none' && visibility!=='hidden' && getClientRects().length>0 && rect 宽高>0`（视觉规格 §1.5-2）。**视觉规格原 §1.5-2 与 §3.2 对照表已同步改写**，全仓不得再出现以 `offsetParent` 作可见性判据的表述。 |
| **C-9** | 残留层强制收尾 | 进入 `#screen-result` / `#screen-finale` 前调 `SD.Guide.forceCleanup()`：若标记**未写**则写 `skipped`，**已写则保持原值**（不得把 `done` 改回 `skipped`），随后移除层与监听。 |
| **C-10** | `#btn-help` 结束后行为 | 改为打开「帮助」菜单（`UI.openModal`，两项顺序固定：① 玩法说明 ② 重看操作指引）。`modalHowto()` 内容一字不改，玩法说明入口不丢。QA G-29 判据放宽为「`#modal-root .modal` 存在 + 菜单首项一击可达玩法说明」，属**判据修订**而非放宽断言，须在报告记录。 |
| **C-11** | `RESPONSE_BUDGET` | 视觉规格未声明响应预算上限 → 该项记 **「未覆盖」**，采集数据但不判定，结论中显式写出；不自行编造阈值（QA 判据①）。 |
| **C-12** | 真人路径 G-55 | 自动化路径由 `tools/guide-smoke.cjs` 用**纯 UI 操作**（`goto`/`click`/`keyboard`/`isVisible`/`screenshot`，不注入 `addInitScript`、不访问 `SANDENG_API`/`SD`）录制逐帧截图。报告 `humanPath.watchedBy` 如实填 **「制作人（AI 视觉复核，非真人玩家）」**，`verdictNote` 明确写「真人试玩待用户本人完成」，**不虚报「有人玩过」**。 |
| **C-13** | QA #C-09「一击重看变菜单两次点击」 | 设计案 3.3：顶栏 `#btn-help` → 帮助菜单（① 玩法说明 ② 重看操作指引），共两次点击 | QA 记为「需求偏差，待制作人拍板」 | **按设计案 3.3 执行，接受两次点击，不改实现** | `#btn-help` 现有行为是 `modalHowto()`（QA 附录 B M-08 已实证），直接改造成「再看一次」会**丢失玩法说明入口**（QA W-04 / G-29 阻断级误伤）。两次点击换取入口不丢，属已接受的低风险取舍（设计案第七章亦列为「低」）。若用户强烈反馈，另立 v1.2 新增独立顶栏按钮，本版不临时改。 |
| **C-14** | `#btn-help` 命中层形态（视觉规格 14:12 又改回独立 `.guide-help-catch`） | 设计案 3.4 / 5.4-5 / 5.0 终稿：**实现中立** —— 「独立 catch 或全屏 `.guide-scrim` 矩形命中判定均可」，并明确**采纳**单一全屏 `.guide-scrim` 方案 | 视觉规格 14:12 版采用独立 `.guide-help-catch` 消费式承接 | **实现采用「单一全屏 `.guide-scrim` ＋ `#btn-help` 豁免洞 rect 坐标判定」**（设计案已采纳方案）；独立 catch 视为等价可选、**不强制**；不设 `z-index:21` | 两方案功能等价且都满足「消费式、零透传、命中→跳过、矩形外→吞掉」。实现侧已按此落地，不为文档来回切换而反复改代码。`#btn-help` 引导期不接收 DOM click、不进气泡焦点陷阱；跳过路径为气泡「跳过」/ `Esc` / 豁免洞矩形点击。设计案 5.4 要求清除的 `z-index:21` 已从 CSS 移除，仅保留琥珀描边态。**G1 的豁免洞是「不铺暗色的可见性切口」，不是高亮洞**，故「G1 整屏无高亮洞」仍成立。 |
