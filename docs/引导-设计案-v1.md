## 0. 设计意图基准（守护用，非新增确认）

核心玩法已由制作人《开工对齐单》与用户拍板确认，本轮为迭代档，**不重开方向确认**。以下 5 行只作守护基准，用于判定步骤与文案是否偏离：

1. 一句话定位：一夜三客、一人为「无相」的本地 AI 推理游戏。
2. 怎么操作：点客人 → 挑语气 → 点话头（＝问一句，耗一盏灯）→ 比对证词与物证 → 点灯指认。
3. 一局怎么玩：六盏灯内问出矛盾，客人会记住并因状态变化改口；三夜为一局。
4. 赢的条件：灯尽前指认出证词与柜上物证对不上的那一位。
5. 一句话亮点：六盏灯的预算，逼你把每一句问在刀刃上。

**本设计案只守护一件事：引导的终点是「玩家会问第一句话」，不是「玩家已经问过第一句」。** 引导结束时六盏灯必须一盏未动，玩家亲手点下第一张话头卡才算闭环。

### 2.1 文案硬约束（视觉与实现必须遵守）

- 每条正文 **≤40 字**（含标点），中文，掌柜 / 灯 / 无相 口吻；**不许出现表格、参数、章节标题、快捷键清单**。
- **禁止即时祈使**（「现在点一下试试」「先点一位客人」）。引导全拦截真实点击，玩家点了不会有反应；一律用「等下 / 现在（仅 G6 交还）/ 记进 / 拿去对」等陈述或未来式。G6 是唯一允许「现在」的一步，且其含义是**引导即将结束后的动作**。
- 术语与现有界面逐字一致：话头、证词簿、柜上物证、温问 / 逼问 / 示物、点灯指认、灯。**不临时造词**（不写「线索卡」「对话按钮」「能量」等）。
- 不得把 `#btn-listen`「添茶 · 缓一口气」描述成「问一句」；不得把 `#btn-accuse` 描述成「直接指认」（它先弹 `modalAccuse` 选人）。
- `#col-right` / `#btn-accuse` / `#ai-panel` **在 v1 中不是任何步骤的锚点**；G6 正文只作文字预告。若后续要导览 AI 面板，另立 v2，本版不做。
- **全部锚点选择器均已按 `index.html` / `assets/style.css` 核实存在**：`.action-dock` 是 class（`index.html` 为 `class="action-dock panel"`），**不存在 `#action-dock`**，本文件一律用类选择器；同理 `.topbar` / `.game-grid` / `.col-center` / `.tb-center` / `.tb-right` 均为 class。逐项清单与层级事实见 5.0。

### 3.3 重看入口挂载（唯一）

- 挂在**顶栏 `#btn-help`（「?」）**，不新增顶栏 DOM 元素。
- 点击 `#btn-help` → `UI.openModal` 打开「帮助」菜单，含两项，顺序固定：
  1. **玩法说明** → 沿用现有 `modalHowto()`，内容一字不改；
  2. **重看操作指引** → 启动引导。
- 启动顺序契约：`UI.closeModal()` → 下一帧（0 ms）从 G1 启动引导；**禁止**菜单弹窗与引导层同时存在。
- 仅 `App.screen === 'game'` 时「重看操作指引」可用。结算 / 通关屏不渲染顶栏，该入口天然不可达。
- 引导期间 `#btn-help` 语义临时改为「跳过」，不打开帮助菜单；引导结束恢复菜单语义。
- 封面屏的 `data-modal="howto"` 「玩法说明」链接行为不变，老用户查规则仍是一击可达。

### 3.4 拦截契约（关键）

- 遮罩层 `position:fixed; inset:0; z-index:20; pointer-events:auto`，**覆盖整屏（含高亮洞区域）**。高亮效果用 `box-shadow` 描边或 4 片遮罩拼接实现，**高亮框元素本身 `pointer-events:none`**，绝不把点击透传给下层锚点。
- **唯一例外**：`#btn-help` 豁免洞区域不绘制暗色背景；引导层内**唯一命中层**（`.guide-scrim` 或等效 catch，`pointer-events:auto`）覆盖该区域并做矩形命中判定：
  - 命中 `#btn-help` 矩形 → 只调用「跳过」（写 `skipped` ＋ 收尾），`preventDefault()/stopPropagation()`，**不派发到 `#btn-help`、不下传游戏**；
  - 命中矩形**之外** → **一律吞掉（no-op）**：不跳过、不推进步骤、不下传游戏。
  这是消费式捕获，不是点击透传。**禁止「点遮罩任意处即跳过」**——那会让玩家误触退出，并使「每步常驻跳过」失去意义。**元素名不强求**（全屏 scrim 或独立 catch 功能等价，此为设计弹性）；但**本版落地实现固定为「单一全屏 `.guide-scrim` ＋ rect 坐标判定」**（裁决单 C-2 / C-14 终裁），结构验收按「**无独立捕获层节点**」执行，3.4 的元素名中立**不作为结构验收依据**。
- 在 `document` **capture 阶段**注册 `keydown`：引导期间对除引导自身快捷键外的全部按键 `stopImmediatePropagation()`；`Esc` 映射为「跳过」；完成 / 跳过时**注销该监听**。
  > 理由（读码结论）：`main.js` 的冒泡 `keydown` 只在 `document.querySelector('.modal-mask')` 存在时提前 return；引导层不是 `.modal-mask`，故 `Q/W/E/R/T` 会直接 `doAsk()` **耗 1 盏灯**，`L` 会 `doListen()` 再耗 1 盏，`1/2/3` 改选客人、`A`/`C` 弹窗。
- 引导自身快捷键（**由 capture 监听消费，不下传游戏**）：`←`＝上一步、`→` / `Enter` / 空格＝下一步（G6 为「知道了 · 去问第一句」）、`Esc`＝跳过；其余按键一律吞掉。视觉侧只需保证键位可达、焦点可见、不吞键，点击 / 按键的流程后果归 3.2 与 3.4。
- 引导层**禁止调用** `Game.dispatch` / `doAsk` / `doListen` / `UI.paint` / `SANDENG_API.dispatch`，禁止修改 `#tb-lamps`、灯计数、`#statement-list`、`#clue-list`、`#dialogue`、`sandeng.save.v2`。
- 引导状态**只存内存、不落盘**；不写任何中间进度。

## 五、误伤评估（逐条 ＋ 规避要求）

### 5.0 已核实的选择器与层级事实（本评估的基准）

**选择器存在性**：本设计案只使用真实存在的选择器。**`#action-dock` 不存在**（`index.html` 中是 `class="action-dock panel"`），一律用类选择器 `.action-dock`；同理 `.topbar` / `.game-grid` / `.col-center` / `.tb-center` / `.tb-right` 均为 class。已确认存在的 id：`#screen-intro` `#screen-game` `#guest-row` `#tone-group` `#topic-row` `#statement-list` `#clue-list` `#tb-lamps` `#col-right` `#ai-panel` `#btn-accuse` `#btn-help` `#dialogue` `#modal-root` `#toast`。`#guide-layer` 是本版**新建**节点（挂 `body`），非既有元素。

| 层 | z-index | 与引导层（20）的关系 |
|---|---|---|
| `.screen` | 2 | 在下，遮罩可覆盖 |
| `.topbar` | 5（flex item，亦建堆叠上下文） | 在下，须靠豁免洞 ＋ 唯一命中层（本版为 `.guide-scrim`）承接点击 |
| `.action-dock`（≤760px `position:fixed; bottom:8px`） | 8 | 在下，但气泡不得压它 |
| `.col-right.force-show` | 12 | 在下，引导层须高于它 |
| **引导层 `#guide-layer`** | **20**（区间 13–29） | 本版新增层 |
| `.modal-mask` | 30 | 在上，故引导期间禁止任何 modal |
| `#toast` | 50 | 在上，提示正常可见 |

**堆叠上下文结论（创意总监判定，覆盖 v1 初稿的 `z-index:21` 方案）**：`#guide-layer` 挂 `body`，与 `.screen`(z-2) 在**根堆叠上下文**中比较；而 `#btn-help` 被包在 `.topbar`(z-5，flex item 亦建上下文) → `.screen`(z-2) 两层上下文之内，给子元素设 `z-index:21` 只在其父上下文内生效，**永远无法越过 z-20 引导层**。故「提升 `.screen` / `.topbar` 层级」方案**否决**（整体提 `.screen` 会让游戏画面盖过遮罩、破坏高亮聚焦，单独提 `.topbar` 又逃不出 `.screen` 上下文）。采用**常驻豁免洞 ＋ 引导层内消费式命中判定**：暗色遮罩在 `#btn-help` 矩形处不绘制背景使其透出可见，点击由 `#guide-layer` 内的唯一命中层按矩形判定并映射为「跳过」，语义按 3.2 不变。**本版实现采用单一全屏 `.guide-scrim` 兼任唯一命中层（裁决单 C-2 / C-14 终裁，予以采纳）**；独立 catch 仅为等价可选、不强制，**本版不得出现 `.guide-help-catch` / `#guide-help-catch` 等独立捕获层节点**。**`z-index:21` 全规格统一「不使用」**：设计案 3.1 / 5.0 / 5.4、视觉规格 1.3 / 1.4 / 5.3（不设子级 z-index）、裁决单 C-2/C-14、`assets/style.css:408`、`js/guide.js:445` 均已一致；任何文件若仍留该值，一律按无效参数删除。

**窄屏事实**：`≤1180px` 时 `#col-right` 默认 `display:none`（仅 `.force-show` 时以浮层 z-12 出现）——这正是 v0 第 6 步三锚点高亮必然落空的原因，v1 已把 `#col-right` / `#ai-panel` 从锚点中删除；`≤760px` 时 `.action-dock` 固定底部、`≤400px` 时 `.col-left` 由横排变竖排。**存档键 `sandeng.save.v2`** 位于 `js/main.js` 的 `SAVE_KEY`；引导键 `sandeng.guide.v1` 与之完全隔离，不读写存档结构。

### 5.1 会不会挡住真实点击？

**结论：引导期间「有意」全拦截，是设计行为，不是误伤；结束后必须零残留。**

规避要求：
1. 遮罩视觉上必须可辨（暗化 ＋ 高亮洞 ＋ 「操作指引 · 第 N / 6 步」标识），玩家一看就知道为何点不动；
2. 每一步气泡常驻「跳过」，任意时刻可退出；`Esc` 与 `#btn-help` 为等价退出路径；
3. 完成 / 跳过 / 异常收尾时，**必须**移除 `#guide-layer` 节点（含唯一命中层与豁免洞）、注销 capture 键盘监听、恢复 `#btn-help` 原样式与 3.3 菜单语义、清除滚动锁；
4. 禁止遗留任何 `pointer-events:none` 或高层级透明层叠在 `.game-grid` 上；
5. **QA 验收**：结束后连点 `#guest-row` 客人卡、`#tone-group` 语气、`#topic-row` 话头卡、`#btn-listen`、`#btn-accuse`、`#btn-help`、`#btn-ai-toggle` 全部正常响应；且首次点话头卡确实消耗 1 盏灯（证明拦截已完全解除，不是「点了没反应」）。**键盘热键的释放回归须用确定性状态量判定：`turn + 1` ∧ `lamps − 1`（`game.js:117` 无条件执行）；不得以「证词 +1」为唯一判据** —— NPC 可能选择 EVADE / COUNTER / REFUSE / LEAVE / FLEE 而不落证词（`revealed=null`），造成假阴性；此时 `statements` 仅作观察量。此判据只把 oracle 改准，**绝不把期望改成「q 不应触发 ASK」**（引导期吞键另由热键用例覆盖，两者不可混）。详见 QA 附录 I / Q-01。

### 5.2 会不会误消耗灯？

**结论：按 3.4 实现则不会。v0 未覆盖以下 3 个真实风险点，为本轮最重要的修订依据。**

| 风险点 | 机理 | 规避要求 |
|---|---|---|
| **(a) 键盘热键（最隐蔽）** | `main.js` 冒泡 `keydown` 仅在存在 `.modal-mask` 时 return；引导层不叫 `.modal-mask`，引导中按 `Q/W/E/R/T` → `doAsk()` **立即耗 1 灯**；`L` → `doListen()` 再耗 1 灯；`1/2/3` 改选客人；`A`/`C` 弹窗 | 3.4 的 capture 阶段 `stopImmediatePropagation()` 全拦截；`Esc`＝跳过；结束注销监听。**QA 必须单独跑一条：引导中依次按 Q W E R T L 1 2 3 A C，灯数保持 6/6、无弹窗** |
| **(b) 高亮洞转发点击** | G4 高亮 `#topic-row`，若洞把点击透传到 `[data-action="ask"]`，玩家一试就耗灯 | 高亮框 `pointer-events:none`，纯视觉；唯一可点区域是气泡内控件（3.4） |
| **(c) 引导层调用游戏逻辑** | 任何 `Game.dispatch` / `UI.paint` / 改灯显示都会污染真实局 | 3.4 明令禁止；引导只读 DOM 几何，不写游戏状态 |

**QA 验收基线（跑完 6 步后）**：`#tb-lamp-text` 仍为 `6 / 6 盏`；`#tb-lamps` 内 `.lamp.on` 计数 = 6；`#stmt-count` 仍为 `0 条`；`#turn-tag` 仍为「第 0 回」；`SANDENG_API.getState().statements.length === 0`；`sandeng.save.v2` 内容与引导前一致。

补充事实（文案不得写错）：**`#btn-listen` 是「添茶 · 缓一口气 耗 1 灯」的 LISTEN 动作，不是「问一句」**；唯一的提问动作是 `#topic-row` 内 `[data-action="ask"]` 的话头卡。

### 5.3 会不会与已有 `UI.openModal` 冲突？

**风险**：① 复用 `#modal-root` 会与「玩法说明 / 点灯指认 / 摊开比对」弹窗互相清空 `innerHTML`；② `.modal-mask` z-30 高于引导层 z-20，引导中弹窗会盖住气泡；③ 从帮助菜单点「重看」却没先关弹窗 → 两层叠加；④ `modalAccuse` / `modalCompare` 若在引导期被快捷键触发会同时违反 5.2。

规避要求：
1. 引导层用独立 `#guide-layer`，**禁止** `UI.openModal` 承载引导；
2. 启动前置守卫「无 `.modal-mask`」；引导期间**禁止任何 `UI.openModal` 调用**（含 `#btn-help` 玩法说明、`modalAccuse`、`modalCompare`）；
3. 重看启动顺序固定：`UI.closeModal()` → 下一帧启动引导（3.3）；
4. 引导层 z-20 < `.modal-mask` 30，即便异常弹窗也不吃掉弹窗；
5. `#toast`（z-50）不受影响，提示可正常显示。

### 5.4 会不会遮住 `#btn-help`？

**风险**：`.topbar` z-5 低于引导层 z-20，顶栏整体被压住；气泡贴顶时也会盖住「?」。

规避要求：
1. 引导期间在暗色遮罩上为 `#btn-help` 开**常驻豁免洞**（该矩形不绘制暗色背景，使 `?` 透出可见），并由 `#guide-layer` 内唯一命中层做矩形命中判定（命中→跳过、矩形外→吞掉，见 3.4）；**不得依赖子级 `z-index:21`，也不得依赖 `#btn-help` 自身 click**（堆叠上下文限制见 5.0）；
2. 引导期间其语义改为「跳过」，**不打开玩法说明弹窗**（避免同时违反 5.3）；结束恢复 3.3 帮助菜单语义；
3. 气泡定位禁止覆盖 `.tb-right`（含 `#btn-sound`、`#btn-ai-toggle`、`#btn-help`）与 `#tb-lamps`；G6 单洞高亮 `.topbar` 时气泡居中偏下，不压顶栏；窄屏贴顶时下移过 52 px 顶栏；
4. **QA 验收**：G1–G6 全过程「?」可见、点击即退出引导并写入 `skipped`，且不弹出玩法说明弹窗、不触发任何游戏动作；点击遮罩**非 `?`** 区域不得跳过、不得推进、不得下传；结束后 `#guide-layer` 整体移除（含 `.guide-scrim` 与常驻豁免洞），点「?」恢复 3.3 帮助菜单。**本版实现不得存在 `.guide-help-catch` / `#guide-help-catch` 或任何专用于 `#btn-help` 的独立捕获 / 透传节点**（结构断言口径见裁决单 C-14）。
5. **对视觉侧的判定（覆盖《引导-视觉规格-v1.md》的默认结论「遮挡／压暗＋不可点」，并修订 v1 初稿的 `z-index:21` 方案）**：引导中「?」**必须可见、点击可达**，做法为「常驻豁免洞 ＋ 引导层内消费式命中判定」（见 5.0）；v1 初稿「不要透明捕获层」**特指禁止把点击透传给游戏**，与「由引导层唯一命中层消费」不冲突 —— 本版实现采用单一全屏 `.guide-scrim` 兼任命中层（**予以采纳的是 scrim 方案**；独立 catch 仅为等价可选、不作为本版验收依据），已补齐 3.4 的「命中→跳过 / 矩形外→吞掉」判定；**`z-index:21` 全规格统一不使用**，并**清除「`#btn-help` 自身可点 / 可聚焦」的表述**（该按钮引导期不接收 DOM click、也不进气泡焦点陷阱；键盘跳过走 `Esc` 与气泡「跳过」）。G1 的豁免洞是「不铺暗色的可见性切口」、**不是高亮洞**，故第二章 G1「整屏无高亮洞」仍成立。视觉侧只保证「**可见 ＋ 点击可达（经唯一命中层矩形命中判定）**」，**不保证 `#btn-help` 的 DOM 级可聚焦 / 自身可点**；点击后果归本设计案。

### 5.5 会不会高亮到隐藏 / 离屏元素？（本轮新增）

≤1180px `#col-right` 隐藏；≤760px `.action-dock` 固定底部、`.game-grid` 可滚动；≤400px `.col-left` 由横排变竖排。

规避要求：取锚点前判可见性，不可见走第二章降级锚点；切步先 `scrollIntoView`；`resize` 重算；**任何步骤都不把 `#col-right` / `#ai-panel` 当锚点**（v0 第 6 步的致命点）。

### 5.6 会不会污染可复跑验收？（本轮新增）

规避要求：`?autopilot=1`、`?seed=&night=` 直开、续档、第 2 / 3 夜一律不触发；提供 `?guide=1` 强制复跑（不改写标记）与 `?guide=0` 强制抑制；QA 清 `sandeng.guide.v1` 可复现首次。保证 6 张分步截图与工程自检稳定可复现。
