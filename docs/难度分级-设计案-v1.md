## 0. 设计意图守护基准（守护用，非新增确认）

核心玩法已由用户拍板确认并于 v1.1.0 交付，本轮为迭代档，**不重开方向确认**。以下 5 行只作守护基准，用于判定四档参数是否偏离（沿用 `docs/引导-设计案-v1.md` 第 0 章已确认文本）：

1. 一句话定位：一夜三客、一人为「无相」的本地 AI 推理游戏。
2. 怎么操作：点客人 → 挑语气 → 点话头（＝问一句，耗一盏灯）→ 比对证词与物证 → 点灯指认。
3. 一局怎么玩：六盏灯内问出矛盾，客人会记住并因状态变化改口；三夜为一局。
4. 赢的条件：灯尽前指认出证词与柜上物证对不上的那一位。
5. 一句话亮点：六盏灯的预算，逼你把每一句问在刀刃上。

## 一、现状核实：现有三夜曲线与真实取值

### 1.1 夜数曲线 D₀(n) —— 读码所得，非设定

出处 `js/director.js:47–58` 的 `difficulty(night)`，`n = clamp(night, 1, 3)`：

| 夜 n | `lamps` | `clueCount` | `evadeBoost` | `redHerring` | `allowFlee` | `temperature` |
|---|---|---|---|---|---|---|
| 1 | 6 | 2 | −0.60 | false | false | 0.75 |
| 2 | 5 | 2 | 0.00 | true | false | 0.95 |
| 3 | 5 | 3 | +0.55 | true | true | 1.15 |

- `redHerring` 原文为 `n >= 2` → 等价改写为「**起始夜 `rhFrom = 2`**，`redHerring = (n >= rhFrom)`」。
- `allowFlee` 原文为 `n === 3`；因 `n` 已被夹取到 `[1,3]`，等价改写为「**起始夜 `fleeFrom = 3`**，`allowFlee = (n >= fleeFrom)`」。
- 上述两处改写对 `n = 1,2,3` **逐项恒等**，仅用于让「正交叠加」有可加减的整数分量；不是行为变更。

### 1.3 合法区间与调参依据（全部由 1.2 推导，非自由设定）

| 参数 | 合法区间 | 调参依据 |
|---|---|---|
| `lamps` | `[3, 9]` | 下界 3 = `solve()` 的 `lamps >= guests.length`；上界 9 = 最高结局 `chain >= clueCount*2` 在 `clueCount <= 3` 时所需的最大问话数（3×3），再高只增加无信息回合（`Agent.run` guard=24，`js/agent.js:74`） |
| `clueCount` | `[1, 3]` | 下界 1 = `clues[0]`/`mainTopic` 无条件引用；上界 3 = `lamps <= 9` 下保证 `3*clueCount <= 9`，且 `CLUE_TEMPLATES` 共 5 条留余量 |
| `evadeBoost` | `[−1.00, +1.00]` | 现有曲线跨度 −0.60~+0.55；`W.EVADE.evadeBoost = 1.00`（`js/npc.js:36`），超过 ±1 会淹没人格 `bias`（最大约 1.8，`js/core.js:102–108`），破坏「人格差异可观测」 |
| `temperature` | `[0.40, 1.60]` | 下界来自 T5「扰动后概率分布 L1 > 0.05」（`js/agent.js:169`）在 T→0 时失效；上界来自 T6「通关率 ≥70%」在 T→∞ 时动作趋均匀、规则掩码被冲淡；现有 0.75/0.95/1.15 居中 |
| `rhFrom` / `fleeFrom` | `[1,4]` / `[2,4]` | 4 = 三夜内永不触发；`fleeFrom` 下界 2 用于保留「遁走是后期机制」的语义，不放到第 1 夜 |
| `trustMaskBelow` | `[25, 55]` | 下界 > 20（T4 固定 `trust=20` 必须仍被掩码）；上界 55 ≈ 初始信任上沿（`50+rng.int(16)-8 = 42..57`，`js/director.js:121`），再高会让多数客人一开局就锁死交付/交心 |
| `tensionLeaveAt` | `[25, 90]` | 下界 > 20（同上 T4）；上界 90：初始张力 12~29（`js/director.js:123`），`press +9`/`REFUSE +8` 可累积，90 仍可达，过高等于取消离店机制 |
| `fleeSuspicionAt` | `[1, 90]` | 下界 ≥ 1（T4 固定 `suspicion=0` 必须仍掩码 FLEE，否则 `>= 0` 成立）；上界 90 为「几乎不可能遁走」 |
| `suspicionGainScale` | `[0.50, 1.50]` | 乘在 `+6/+8/+2` 上；以 6 盏灯全示物路径 `6*6=36` 为基线，0.50→18、1.50→54，配合 `fleeSuspicionAt` 使遁走在低档难触发、高档可达 |
| `chainMinForFullCredit` | `[1, 6]` | 下界 1（chain=0 时扣分无意义）；上界 6 = `clueCount(3)*guests(3)` 的最大 chain，再高会永久扣分 |
| `endingBestTrust` | `[45, 70]` | 下界 45（初始信任均值约 50，再低则几乎必达、失去评级意义）；上界 70（多轮温问可达上限附近，再高则永不可达） |

## 二、通用维度 → 本作映射（如实映射，含「不适用及原因」）

| 用户通用维度 | 本作对应物 | 承载参数（均见第三章） | 说明 |
|---|---|---|---|
| **敌人强度** | 无相伪装强度 | `clueCount`、`rhFrom`（红鲱鱼起始夜）、`temperature`（决策不可预测性） | 物证话题越多、含糊措辞越早出现、softmax 越平 → 越难读人。**沿用现有曲线语义**：`difficulty()` 把 `clueCount` 1→2、`redHerring` false→true、`temperature` 0.75→1.15 作为加压手段，本规格不反转方向 |
| **敌人强度** | NPC 对抗性 · 避答 | `evadeBoost` | 本作**无独立「避答阈值」**；避答由 `W.EVADE.evadeBoost` 线性效用系数承担（`js/npc.js:36/96`），如实按系数映射，不硬造阈值 |
| **敌人强度** | NPC 对抗性 · 疑心累积 | `suspicionGainScale` | 统一缩放 `+6/+8/+2` 三处增量；不新增第四种疑心来源 |
| **敌人强度** | NPC 对抗性 · 遁走阈值 | `fleeSuspicionAt`、`fleeFrom` | `FLEE` 合法 = `isImpostor && (n >= fleeFrom) && suspicion >= fleeSuspicionAt` |
| **敌人强度** | NPC 对抗性 · 张力阈值 | `tensionLeaveAt`、`trustMaskBelow` | 分别对应 `LEAVE` 开放与 `CONFIDE/GIFT` 锁定 |
| **资源数量** | 灯数 | `lamps` | 唯一行动点；`lampsLeft` 初值 = `lamps` |
| **资源数量** | 物证数 | `clueCount` | 直接来自 `diff.clueCount` |
| **资源数量** | 可用话题数 | **不适用** | **原因**：`C.TOPICS` 恒为 5 且 `listActions()` 每轮对每位在座客人全量枚举（`js/game.js:48–55`），`difficulty()` **无此旋钮**。话题是推理的「信息维度」而非消耗性资源；裁剪话题会让物证话题可能落在可问集合之外，直接击穿 `solve()` 的 `unique` 约束与「证词×物证比对」。且改 `listActions()` 枚举顺序会改写影子掌柜的动作序列 → 200 组种子自检基线全变。**替代承载**：信息量差异由 `clueCount`（需交叉核对的物证话题数）表达，不新增话题裁剪 |
| **时间限制** | 行动点（灯） | `lamps` | 每问一句 / 每添一轮茶耗一盏灯 |
| **时间限制** | 回合上限 | **派生量，非独立参数** | **原因**：`game.turn++` 与 `game.lampsLeft--` 在 `dispatch()` 同一次调用中同步发生（`js/game.js:99/117`），本作**无独立回合计数**，故「回合上限 ≡ `lamps`」。本规格**不新增 `turnCap`**，否则会与 `conclude(game,'lamps')` 形成双终止条件、破坏灯尽自动结算的唯一性 |
| **时间限制** | 实时计时器 | **不适用** | **原因**：本作是纯静态零依赖、`mulberry32` 确定性可复现（`js/core.js:10–39`），案件与 NPC 决策全部由 `seed + night + turn + salt` 决定。引入 `Date.now()` / `setTimeout` 计时会让同一 seed 在不同机器、不同帧率下产出不同结果，**直接破坏逐位复现与端侧零依赖**，且需要在 `game` 状态里挂时间戳 → 改 `sandeng.save.v2`。**明确不引入** |
| **容错率** | 错误指认容忍 | **不适用** | **原因**：v1.1.0 `accuse()` 中 `!correct → gain = −120`、`ending='灯灭'`、`phase='ended'`（`js/game.js:155–160/165`），**错指即终局，无「可错几次」旋钮**。新增容忍度会改写胜负判定与 `game.result` / `snapshot()` 结构，并让「灯尽自动结算」路径分叉。**不硬造** |
| **容错率** | 证据链完整度阈值 | `chainMinForFullCredit` | 现有 `chain < 2 → −120`（`js/game.js:152`）的门槛常量；只影响得分，不影响 `correct` |
| **容错率** | 结局评级门槛 | `endingBestTrust` + 派生 `clueCount * 3` | 现有「灯下留名」门槛（`js/game.js:162`）；不新增系数、不新增第三套评级公式 |
| **容错率** | 可承受的空问/避答次数 | `lamps`（与资源维度同源） | 灯越多，被 `EVADE` / `REFUSE` / `COUNTER` 浪费的回合越能扛住 |

### 3.2 参数终值表

> **本表四档 × 13 项 = 52 个数值，逐项均为【契约】**；「性质」列的【契约】对该行四档同时生效。任何下游文档只引用本表的参数名与数值，不得复述或另立一份难度表。

### 3.3 恒等性契约（保证默认档 = v1.1.0）

`basic` 的 6 个叠加分量全为 **0 / ×1.00**，且 6 个绝对阈值 / 缩放常量 **35 / 70 / 60 / 1.00 / 2 / 55** 逐一等于 `js/npc.js` 与 `js/game.js` 的现有字面量，`rhFrom = 2`、`fleeFrom = 3` 逐项复现 `redHerring`/`allowFlee`。因此对 `n = 1,2,3`：

```
D(n, basic) ≡ D₀(n)　且　六个新字段 ≡ 现有硬编码常量
```

→ **默认档行为逐字节不变**，`selftest(200)` 6/6 与 `node tools/selftest.cjs --seeds 200`（exit 0）不被破坏。这是「默认档 = 初级」不可动摇的理由，也是引导验收基线（`#tb-lamp-text = 6 / 6 盏`）不可动摇的理由。

## 四、判定规则

### 4.1 入口合法性判定与非法 id 拒绝

**合法 id 集合**：`novice` / `basic` / `intermediate` / `advanced`（ASCII 小写，**精确字符串相等**）。

**取值优先级**：

| 场景 | 判定来源 | 规则 |
|---|---|---|
| 新开局（`#btn-start`、`SANDENG_API.newRun`、`?seed=X&night=N` 直开、`?autopilot=1`） | URL `?difficulty=<id>` | 合法 → 采用并写入 `session.difficultyTier`；缺失或非法 → 回落 `basic` |
| `?guide=1` 强制复跑引导 | **忽略 URL `difficulty`** | 一律 `basic` + 第 1 夜（引导是教学场景，必须固定 6 盏灯基线，见 §6.2） |
| 续玩（`#btn-continue` / `continueRun`） | 存档 `session.difficultyTier` | **忽略 URL**，三夜档位必须一致；缺字段 → 回落 `basic`（见 §6.3） |
| 不传档位的调用（`Agent.selftest` / `Agent.run` / `Game.create` 两参 / `SANDENG_API.trace` / `tools/selftest.cjs`） | 默认回落 | 一律 `basic`，**不得**新增 tier 循环 |

**非法 id 判定 = 拒绝，不是宽松解析**：任何不等于四个枚举字符串之一的值 —— 大小写不符、首尾空格、空串、数字 `1/2/3/4`、中文档名、`null`/`undefined`、URL 编码残留 —— 一律**拒绝该值**，回落 `basic`，并向玩家显示**一次**「难度未识别，已按初级开局」提示。

- 禁止 `parseInt` / `includes` / `startsWith` / 模糊匹配；禁止把非法值写进 `session`、存档或 seed。
- **理由**：若非法 id 被接受，同一 `(seed, night)` 会落进不同参数组、生成不同案件，直接破坏「seed 决定案件」的逐位复现契约。
- 缺失 / 默认回落**不写提示**（仅非法 id 写一次），避免污染冷启动 UI 与引导的 DOM 计数基线。

**数据契约**：`App.session.difficultyTier` 存合法 id 字符串；`Game.create` / `Director.generate` 增加**可选第三形参 `tier`**，不传时 = `basic`；前两个实参的顺序与语义不变。运行期 `cs.difficulty` = **原有 7 字段**（`night / lamps / clueCount / evadeBoost / redHerring / allowFlee / temperature`，字段名一个不改）+ **新增 6 个字段**（§3.2 第 7–12 项：`trustMaskBelow / tensionLeaveAt / fleeSuspicionAt / suspicionGainScale / chainMinForFullCredit / endingBestTrust`）= 共 **13 字段**；6 个叠加分量、`rhFrom` / `fleeFrom`、`endingBestChain` 只存在于配置层或为派生量，**不写入 `cs.difficulty`**（避免同一事实两份）。`snapshot()` 的 `sandeng.state.v1` 结构**不改**。

### 4.2 生成期案件约束（每夜重新校验）

1. `clueCount >= 1` 且 `clueCount <= 3`；每条物证话题必须属于 `C.TOPICS`（5 条之一），且来自 `CLUE_TEMPLATES`（5 条）。
2. `lamps >= 3`（`solve().enough` 要求 `lamps >= guests.length`）。
3. 矛盾唯一：`solve()` 对每条物证须 `deviants.length === 1 && deviants[0].id === impostorId`。
4. 理想玩家可解：`Director.idealInference(cs).correct === true`。
5. 重掷上限保持 **60** 次，案件 seed 仍为 `seed|nightN|tryA`；**不得把 tier 拼进 seed**。60 次全失败的兜底标注沿用现状，不加强、不删除。
6. 叠加公式的输出**在生成前已夹取到 §1.3 合法区间**；夹紧结果与 tier 一并记入 `cs.difficulty`，夹紧不得改变 seed。
7. **不得**因档位改变 `buildCase()` 的取值规则（无相在每条物证话题上撒谎、清白客人说真值、红鲱鱼只落在一位清白客人身上）；只改 `clueCount` / `redHerring` 两个开关量。

### 4.3 运行期判定（灯尽 / 证据链 / 遁走）

| 判定 | 规则 | 本规格改动范围 |
|---|---|---|
| 耗灯 | `ASK` / `LISTEN` 各 `turn++ ; lampsLeft--`；`ACCUSE` 不耗灯 | **不改**，只改 `lamps` 初值 |
| 灯尽 | `lampsLeft <= 0` → `conclude(game,'lamps')` → 按 `belief()` 最大者自动 `accuse` | **不改路径**，不叠加第二终止条件 |
| 回合上限 | ≡ `lamps`（推导见 §2） | **不新增 `turnCap`** |
| 证据链 | `evidenceChain()` 按「每条物证话题 × 每位有证词的客人」计数，上界 `clueCount*3` | **不改函数**；`chainMinForFullCredit` 只替换 `chain < 2` 的门槛常量，不影响 `correct` |
| 遁走 | `FLEE` 合法 = `isImpostor && (n >= fleeFrom) && suspicion >= fleeSuspicionAt`；触发 → `conclude(game,'flee')` → `空盏` / `score 60` / `correct false` | 只替换 `allowFlee` 与 `60` 两个判定量 |
| 离店 | `LEAVE` 需 `tension >= tensionLeaveAt`；`left=true` 后该证词路径关闭，`leftCount>0` → 结局降为 `一灯独明` 且 `gain -= 80` | 只替换 `70` |
| 交付/交心锁定 | `trust < trustMaskBelow` → `CONFIDE`/`GIFT` 掩码 | 只替换 `35` |
| 疑心累积 | 三处 `+6/+8/+2` 统一乘 `suspicionGainScale`，结果仍 `clamp(0,100)`；`calm` 仍由 `tension` 派生 | 只新增一个缩放因子；`basic` = 1.00 恒等 |
| 实时计时 | 无 | **明确不引入** |

### 4.4 结局评级

- `correct` 判定不变：`guestId === cs.impostorId`（`js/game.js:144`）。
- `ending` 优先级不变（`js/game.js:159–163`）：`!correct → 灯灭`；`leftCount > 0 → 一灯独明`；`chain >= clueCount*3 && avgTrust >= endingBestTrust → 灯下留名`；否则 `破晓`。
- 评分公式不变（`js/game.js:151–156`）：`600 + lampsLeft*40 + chain*35 + round((avgTrust-45)*2)`；`chain < chainMinForFullCredit → −120`；`leftCount > 0 → −80`；`max(120, gain)`；错指 `−120`；遁走 `60`。
- 评级门槛**只允许**经 `clueCount`（派生 `clueCount*3`）与 `endingBestTrust` 调档；**不得**新增第三套评级公式或独立系数。
- 三夜总评称号（守夜人 / 掌灯人 / 值夜人 / 夜行人，`js/main.js:147–148`）**不随档位变化**，避免同一份成绩在不同档显示不同称号、破坏成绩可比性。
- **唯一允许的文案增补**：`shareText()` 追加一行「难度：\<中文名\>」（`js/main.js:160–167`），其余文案一字不改。**理由**：非默认档的复现主键是 `(seed, night, tier)`，分享文本不带档位则同 seed 无法复现（见 §6.4）。

## 五、正交叠加、公式与判据④极值可达性验证

### 5.1 「正交」的定义

- **档位分量 `T(tier)`**：只提供**跨夜恒定**的基准量（偏置 / 倍率 / 起始夜位移 / 绝对阈值），不读取 `night`，不在 `night` 上分支。
- **夜数分量 `D₀(n)`**：只提供**跨档恒定**的三夜曲线（§1.1），不读取 `tier`。
- 二者不互相覆盖、不互相读取、不共享同一字段的写入权；运行期终值 `D(n, tier)` 是二者的**纯函数**，与调用顺序、存档、URL 历史无关。
- **不是**「四档替代三夜」，也**不是**「三夜里再分四档」：任意档位都必须完整跑完三夜，任意夜次都可使用任意档位，共 **4 × 3 = 12** 组合。

### 5.2 叠加公式（数学定义，非代码）

记 `夹(x, a, b)` 为把 `x` 限制到闭区间 `[a,b]`；`取2(x)` 为四舍五入到两位小数（`Math.round(x*100)/100`，与 `C.round(x,2)` 一致）。**运算顺序按下列公式从左到右写死，不得交换**；整数项不做取整。

```
lamps(n,t)             = 夹( D₀.lamps(n) + T.Δ_lamps , 3 , 9 )
clueCount(n,t)         = 夹( D₀.clueCount(n) + T.Δ_clueCount , 1 , 3 )
evadeBoost(n,t)        = 夹( 取2( D₀.evadeBoost(n) + T.Δ_evadeBoost ) , −1.00 , +1.00 )
temperature(n,t)       = 夹( 取2( D₀.temperature(n) × T.k_temperature ) , 0.40 , 1.60 )
rhFrom(t)              = 夹( 2 + T.Δ_rhFrom , 1 , 4 )      →  redHerring(n,t) = ( n ≥ rhFrom )
fleeFrom(t)            = 夹( 3 + T.Δ_fleeFrom , 2 , 4 )    →  allowFlee(n,t)  = ( n ≥ fleeFrom )

trustMaskBelow         = T.trustMaskBelow          （跨夜恒定）
tensionLeaveAt         = T.tensionLeaveAt          （跨夜恒定）
fleeSuspicionAt        = T.fleeSuspicionAt         （跨夜恒定）
suspicionGainScale     = T.suspicionGainScale      （跨夜恒定）
chainMinForFullCredit  = T.chainMinForFullCredit   （跨夜恒定）
endingBestTrust        = T.endingBestTrust         （跨夜恒定）
endingBestChain(n,t)   = 3 × clueCount(n,t)        （派生，不设独立数值）
```

**恒等性证明**：`T(basic)` 的 6 个叠加分量为 `0 / ×1.00`，故前 4 式退化为 `D₀` 原值；`rhFrom=2`、`fleeFrom=3` 对 `n∈[1,3]` 与 `n>=2` / `n===3` 逐项相等；后 6 个阈值等于现有字面量。故 `D(n, basic) ≡ D₀(n)` 对三夜全部成立（§3.3 实测已确认）。

**取2 的必要性**：`temperature` 若保留浮点尾数（如 `1.15×1.1 = 1.265000…`），跨浏览器 / 跨 Node 的 `softmaxSample` 指数计算可能出现末位漂移，破坏逐位复现。故倍率结果一律先取两位小数再入公式。

### 5.4 判据④ 一致性 + 可达性（极值跑一遍）

对齐 `docs/引导-验收用例-v1.md` 四-④「一致性 + 可达性（极值跑一遍）」及其中「上限/系数可达性证明」条目：**期望值不来自被测常量、不反读实现**（判据①），而是把两端极值**实际代入叠加公式跑一遍**，证明输出落在合法区间、两端都可达。

本轮验证方式：`node -e` 独立复算 §5.2 公式（不 require 任何 `js/` 模块），遍历全部 12 组，逐项比对 §1.3 合法区间。**实测结果**：`ALL_IN_BAND=true, violations=0`，进程 exit 0。

| 极值组合 | 代入结果 | 合法区间校验 | 可达性结论 |
|---|---|---|---|
| **新手级 × 第 1 夜**（下界极值） | `lamps=8, clue=1, evade=−0.80, T=0.68, rhFrom=4, fleeFrom=4, trust=25, tension=80, susp=80, suspGain=0.70, chainMin=1, endTrust=45` | 12 项全部落在 §1.3 区间内；`lamps=8 ≥ 3` 满足 `solve().enough`；`redHerring=false`、`allowFlee=false` | **可达**：案件可解；`lamps(8) ≥ 2×clueCount(2)=4` → 「灯下留名」数学上可达；无遁走、无红鲱鱼，为最宽容一端 |
| **高级 × 第 3 夜**（上界极值） | `lamps=3, clue=3, evade=+0.85, T=1.38, rhFrom=1, fleeFrom=2, trust=45, tension=60, susp=48, suspGain=1.40, chainMin=3, endTrust=65` | 12 项全部落在 §1.3 区间内；`lamps=3 ≥ 3` 满足 `solve().enough`；`clueCount=3 ≤ 3`；`T=1.38 < 1.60` | **可达**：案件仍可解、三个新阈值均 > T4 固定输入（45/60/48 > 20/20/0）；`2×3=6 > 3` → 「灯下留名」数学上**不可达**，属设计意图（高档评级更严），**不是缺陷**，见 §7 R3 |

**一致性**：`basic` 三行逐项等于 `D₀(n)` 与现有字面量（§3.3 实测输出已给出）；同一参数在 §3.2 契约表、§5.2 公式、§5.3 派生表三处无互相否定陈述；12 组无任何一项需要靠「夹取」才勉强进区间（夹紧未实际触发）→ 契约表自身是自洽的，不依赖兜底夹紧掩盖越界。

> **对 QA 的接口**：四档的验收用例与可复跑断言清单由 qa-lead 另行产出，**只引用本文件 §3.2 / §5.3 的数值作为写死期望值**，不并入 `Agent.selftest()` 的 6 条用例（保持 6/6 基线语义，见 §6.1）。
