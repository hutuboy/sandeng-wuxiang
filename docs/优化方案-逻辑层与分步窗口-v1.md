| 你的诉求 | 本方案的解法 | 落点 |
|---|---|---|
| 分级仍太简单 | 把「计数找说谎者」升级为**布尔逻辑定位**：∧ ∨ ¬ ⊕ 四种算子全部进玩法 | §2 |

## 2. 问题一：逻辑层重建（∧ ∨ ¬ ⊕ 全部用上）

### 2.1 目标
把「无相是谁」从**计数匹配**改为**解一条布尔判定式**：每位客人有 5 个属性（来路/时辰/同行/行囊/信物），「无相」由一条**隐藏的命格条件式 `F`** 唯一定义，玩家要把散落的线索拼成与 `F` 等价的式子，用真值表筛出唯一客。

### 2.2 命题模型（原子 + 算子）

**原子命题（谓词）**：`P(客人, 话题, 关系, 值)`，关系 ∈ {`=`, `≠`}，例：
- `沈砚·来路 = 北坡`
- `白九·同行 ≠ 独行`

**四种算子（全部进玩法）**：

| 算子 | 符号 | 玩法含义（叙事化） | 玩家怎么用 |
|---|---|---|---|
| 与 | ∧ | 「两说并存」——两条都成立才收窄 | 合并两条硬证 |
| 或 | ∨ | 「非此即彼」——二者居一即可 | 先框定候选池 |
| 非 | ¬ | 「排除法」——证伪一条 | 剔除误导/红鲱鱼 |
| 异或 | ⊕ | 「二证相左，必有一伪」——恰好一真 | 判断**哪份证词可信**，再以可信者为基 |

> 关键：⊕ 是「元判断」——它作用在**两份证据的可信度**上（如「更夫簿」与「路引」只有一个可信），迫使玩家先裁决信源，再推理。这是当前完全没有的层次。

### 2.3 难度 = 逻辑深度（替换「数量堆叠」）

| 档 | 逻辑深度（必须用到的算子） | 一个整例 | 需要的步数 |
|---|---|---|---|
| 新手 | 单谓词 `=` / `≠` | 「无相携药箱」 | 3~4 |
| 初级 | ∧ **或** ∨（二选一） | 「无相来自北坡 **且** 三更到」 | 4~5 |
| 中级 | ¬ + (∧/∨) | 「无相**不是**独行，**且**携刀匣」 | 5~6 |
| 高级 | ⊕ + 嵌套 | 见 §2.5 | 6~8 |

> 与现有 `difficulty.js` 的关系：`lamps / clueCount / temperature` 等**继续保留**（叙事与压力轴），但新增一条 `logicDepth` 轴，作为「分级」的主区分度。

### 2.4 生成器改造（`director.js`）

新流程（仍是确定性 seed 生成）：
1. 抽 3 客 + 定无相。
2. 生成属性表（同现状）。
3. **按档位抽算子组合**，构造目标式 `F`：`atoms + ops`，深度由 `logicDepth` 决定。
4. 分配属性，使**恰好一位**满足 `F`（枚举校验，见下）。
5. 生成证词 + 线索，保证「拼出与 F 等价的式子」所需的原子**全部可获得**，并投放红鲱鱼（`¬` 的对象）。
6. **唯一性求解器 `solveLogic(cs)`**：枚举 3 客 × 5 属性真值，断言「满足 F 者恰好 1 人」，且「存在一条最小等价式」。不满足则重掷（沿用现有 60 次重掷机制）。

**这是真正的约束求解**——比现状的「矛盾唯一」更强，也直接支撑「AI 运用」维度（可解释、可复算、可展示求解轨迹）。

### 2.5 高级整例（∧ ∨ ¬ ⊕ 一次全用上）

命格残卷给出：
- 残一（∨）：无相来路，**非北坡即东市**。
- 残二（∧）：无相**既**携刀匣、**又**在三更到店。
- 残三（¬）：无相**并非**独行。
- 残四（⊕）：更夫簿与路引二证，**只有一证可信**。

玩家在推演台组合：
```
[(来路=北坡) ∨ (来路=东市)]
  ∧ [(行囊=刀匣) ∧ (时辰=三更)]
  ∧ ¬(同行=独行)
```
先用 ⊕ 裁决「更夫簿 vs 路引」哪份可信，再代入真值表 → 恰好一人全真 → 指认。

### 2.6 推演台（新玩法核心）

一个独立窗口，三块：
- **候选区**：3 位客人的属性表（已由证词 + 物证校订出的「推定真值」）。
- **命题卡区**：每条证词/线索是一张卡，卡面显示原子与已知真值（T/F/未定）。
- **算子槽**：把卡拖入槽位、在槽间插 ∧ ∨ ¬ ⊕，**实时**对 3 位候选求值，显示真值向量（如 `[真, 假, 假]`）。
- **目标提示**：「写出一条使**恰好一人**成立的式子」——当向量只剩一个「真」，该客即无相，可进指认。

> 交互降门槛：新手/初级默认「回填式推演」（给半成品式子，玩家补算子/补卡）；中高级才是「自由拼装」。避免一上来就让休闲玩家懵。

## 3. 问题二：分步多窗口（一窗一步，走完出结论）

### 3.1 目标
把当前「单屏三栏仪表盘」（物证 + 证词簿 + 对话 + AI 轨迹挤在一屏）拆成**情节化的一幕一窗**，与「标准游戏操作步骤」一致。

### 3.2 五幕结构（每幕 = 全屏独立窗口，顶部有「第 n / 5 幕」+ 余灯）

| 幕 | 窗口内容 | 解决什么 |
|---|---|---|
| ① 点灯 | 选难度 + 序言 + 命格残卷（线索总览） | 开场凝聚 |
| ② 逐客问询 | **每位客人一窗**：只放该客立绘 + 对话 + 问话控件（语气/话头）；问完「落灯」→ 下一位 | 消除三栏拥挤，聚焦单客 |
| ③ 推演台 | §2.6 的命题卡 + 算子槽 + 真值表 | 新增玩法核心 |
| ④ 指认 | 选人 + 点灯确认（余灯压力） | 决策收束 |
| ⑤ 结案 | 现有 `screen-result` + 复盘三段 | 复用现有 |

> 可直接复用现有 `UI.showScreen(id)`（`js/ui.js:211` 的 `['screen-intro','screen-game','screen-result','screen-finale']` 数组）：把 `screen-game` 拆成 `screen-ask`（逐客） + `screen-deduce`（推演台） + `screen-accuse`，或用一个 `screen-step` 容器按 `stepIndex` 切内部模板。

### 3.3 状态机（最小改动）

在 `js/main.js` 的 `App` 增加 `step` 字段（`'lamp' | 'ask' | 'deduce' | 'accuse' | 'result'`），`ask` 再带 `askGuestIndex`。每幕结束推进 `step`；`ask` 三位问完自动进 `deduce`；`deduce` 得出唯一解才解锁 `accuse`。**游戏逻辑层（`game.js`）几乎不动**，只在外层加「步骤门」。

### 3.4 视觉与节奏
- 转场用「灯火推移」（现有 `bg-canvas` + `grain` 可复用）。
- 每幕只保留**一个主行动**，其余折叠为角标（余灯、已收命题数）。
- 移动端天然适配：一窗一屏，不再横向挤。

## 6. 验收方案（新增不变量）

1. **唯一解**：200 seed × 4 档，`solveLogic` 均「满足 F 者恰好 1 人」。
2. **可解性**：存在一条只用「已投放线索所含原子」构成的最小等价式。
3. **算子覆盖**：高级档 200 局中，∧ ∨ ¬ ⊕ 各自出现率 > 0（防「假高级」）。
4. **旧回归**：`selftest 6/6`、`guide-smoke 60/60`、`difficulty-smoke PASS`、`browser errors=[]` 全绿。
5. **真人**：至少 3 位非作者各试玩 1 局，记录「是否理解推演台」「是否觉得比计数法更难」。

### 9.2 与方案的偏差（及原因）

| 方案写的 | 实际做法 | 原因 |
|---|---|---|
| 拆成 5 个互斥的独立屏 | 同一 `#screen-game` 内的**四扇窗 + 一屏结算**，用 `#act-windows[data-act]` 切显隐 | 保持所有既有 ID / 事件委托 / `UI.paint` 不变，60 项引导门禁只需改 2 个常量即可继续覆盖，不必推倒重写 |
| 「点灯」是新一夜的必经幕 | 从封面「点灯 · 开始守夜」进来时**跳过**点灯幕（封面即点灯）；第二/三夜「接着守下一夜」进来才走点灯幕 | 封面上那颗按钮本来就写着「点灯」；同时避免所有既有自动化路径因多一步而全部失效 |
| 推演台是新弹窗 | 第三幕**内联**渲染，弹窗入口（证词簿「推演台」/ `D` 键）保留 | 幕内直接看表更顺；弹窗留给「边问边看」的临时查阅 |
| `¬` `⊕` 留到 P2 | **提前落地**：`¬`（NAND，并非全部不符）与 `⊕`（恰一不符）已在推演台可切 | 你的原话是「与或非异或要**全部用上**」；这两个算子成本极低，缺了反而显得是半成品。P2 剩下的是「让生成器出带 ¬/⊕ 结构的题」 |

### 9.3 踩到的两个真坑（已修，写进注释防复发）

1. **`.act` 不能带 transform 动画**。`animation: actIn ... both` 的填充期让 `.act` 成为 fixed 后代的包含块 —— 窄屏吸底操作台（`.action-dock`）会被钉在 `.act` 底部而不是屏幕底部，每次切幕都跳一下。终态改成**纯 opacity 淡入**。
2. **G2 锚点从 `#guest-row` 改到 `#guest-switch`**。单客窗高 224px，加上气泡 245px 与吸底操作台 184px，390×844 上垂直空间不够，气泡必然压住高亮洞（G-93b 失败）。换人条只有 44px，语义上又正好对应「上方换人」。
   > **v1.7.2 已作废**：换人条撤掉后 G2 锚点回到 `#guest-row`（三行卡的整块，239px）。气泡改落在它下方——那一片是物证条，G2 时还没开始问，物证本来就只是清单，可接受；三行卡全在洞内、一个都没被遮，G-93 仍 0 重叠。

### 9.4 门禁结果（v1.7.0）
