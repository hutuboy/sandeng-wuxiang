### 0.3 硬边界（不可动，违反即退回）

1. **不改核心功能与玩法规则**：任何判定只动「怎么说」，不动「做什么」。
2. **引导 G1–G6 六步是 60 项自动化验收对象**：步骤数 `TOTAL=6`、步骤 `id`（G1…G6）、顺序、锚点 `anchor/fallback/secondary`、`data-guide-step`、`data-guide-step-total`、`aria-current`、按钮 `id` 与 `data-action`、`guide:step` 事件的 `stepNo/stepId`、存储键 `sandeng.guide.v1` —— **一律不动**。仅允许精简 `STEPS[].title / body` 的措辞长度。
3. **必须保留**：四档难度名称（新手级 / 初级 / 中级 / 高级）、`seed`、`余灯数`、AI 决策轨迹、证据链与得分等可复现性 / 评分取证信息。
4. **顶栏「?」重看引导入口必须保留**，不得因精简而失去可达性。
5. 术语前后一致：统一用「话头 / 物证 / 证词簿 / 余灯 / 夜次 / 点灯指认 / 无相 / 影子掌柜 / 难度档位」，不临时造词。

### 0.4 判定原则（决定谁留谁删）

按「玩家此刻是否要用它做决策」排序，四级：

| 级别 | 定义 | 处置 |
|---|---|---|
| L1 决策信息 | 不看就无法做下一步判断（余灯、夜次、物证真值、话头、证词、AI 决策理由） | 保留，只允许排版级精简；进入白名单 |
| L2 操作信息 | 说明按钮后果、代价、快捷键 | 精简为动词短句，禁止删除 |
| L3 引导信息 | 首次教学、帮助菜单 | 保留但去重复、去铺垫；受验收约束，降幅克制 |
| L4 氛围 / 工程自述 | 世界观渲染、AI 原理、参赛信息、零依赖声明 | 折叠、合并到唯一载体，或直接删除 |

**层级结论**：一屏只留一个 L1 主信息与一个 L2 主操作；L4 一律下沉到「关于」或折叠层，不得占据首屏与结算页的主视觉带。

## 一、核心设计概览

这是一款「一夜三客、六盏灯、问一句灭一盏」的推理游戏，玩家的核心动作只有三个：**选人 → 选话头发问 → 点灯指认**。当前界面的问题不是写得不好，而是**同一件事在四到六个地方各写了一遍**：核心规则出现在封面、G1、玩法说明、分享文案；AI 原理出现在封面、玩法说明、关于、AI 面板空态、分享文案；免责声明出现在指认弹窗、比对弹窗、结算页置信度标题。玩家在 30 秒内要读完 3000 余字说明才能开始第一句问话，而余灯和物证真值这两个真正影响决策的数字反而被淹没。

本轮不做功能裁剪，只做三件事：**删 L4、并重复、把 L1/L2 顶到层级最前**。所有删除都指定「唯一保留位置」，保证信息不丢失、只是不再重复出现。

## 八、风险与可砍项

### 8.1 风险

| 编号 | 风险 | 影响 | 缓解 / 处置 |
|---|---|---|---|
| R-1 | **改 G1–G6 文案可能触发 60 项验收中的逐字断言** | 验收红灯，阻塞上线 | 本规格只改 `title/body` 措辞长度，所有标记不动（D7）。**若查明验收含逐字文案断言，本组 6 条判定一律降级为「保留」**，其余 80 条不受影响 —— 宁可不精简，不可破验收 |
| R-2 | 删封面 `intro-sub` 技术枚举会削弱「AI 原生」首屏传达（评奖观感） | 首屏卖点变薄 | 保留一行 `三位客人由本地 AI 自主决策，会记住你说过的每句话`（J004）；完整原理仍在「关于」，且 AI 决策轨迹面板是对局屏常驻证据 |
| R-3 | **`btn-finale-agent` 名实不符**（文案「看影子掌柜复盘」→ 实际 `modalDefect()` 缺陷复现） | 玩家点开看到 JSON，认知断裂；且与工程自检重复 | 本轮**只改文案/删除按钮**（V11）；若主理人希望保留工程演示入口，须由主程序改绑 `openAgentTrace()` 并同步文案，属功能侧改动，需单独确认，不在本规格内擅自执行 |
| R-4 | 折叠 L4 后，QA / 评分取证路径变长 | 取证时需多点一次 | 白名单 8 项（含 seed、四档、余灯、证据链、AI 轨迹）**一律不折叠**；折叠的只有原理说明与赛事署名 |
| R-5 | 结算页「真相摊开 / 复盘卡」合并过度会丢掉「漏掉的物证」这一学习反馈 | 玩家不知道下一夜该改什么 | 复盘卡三项（漏掉的物证 / 自相矛盾 / 门槛差距）**全部保留**，只删重复的真值复述与「用灯 X/Y」；R10/R12 已指定唯一载体 |
| R-6 | 动词化把「点灯开局 / 再开三夜 / 重开本夜」统一为「开」字族，可能被误读为都会清存档 | 误触损失 | 按钮 `title` 保留后果提示（「开新局会覆盖当前存档」等，由主程序补），且 `#btn-continue` 的动态夜次命名 V02 明确区分「续」与「开」 |
