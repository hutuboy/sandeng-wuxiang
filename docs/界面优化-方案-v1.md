> 目标：**只动「怎么呈现」，不动「玩什么」**。
> 交付形态：可直接落地的布局 / 文案 / 视觉规格 / 实施清单 / 验收判据。
> 当前基线：线上 v1.4.1（魔搭创空间 Static，公开，免费 CPU）；本地回退锚点 = tag `v1.4.1` → commit `69d7b38`。

## 0. 一句话结论

对局屏的问题是**「所有信息同权重」**：三栏等权、11 档字号、约 60 个可见信息单元里七成 ≤11px，
而真正决定一局胜负的「选谁 / 问什么 / 还剩几盏灯 / 何时指认」被埋在同尺寸的灰卡里。
方案不删任何功能、不改任何状态机，用 **三层信息架构 + 6 档字号 + 7 处去重 + 主操作热区强化** 收口。

> **v1.1 会签修订**：四路规格落盘后共发现 **12 处口径冲突**，已逐条裁决（§12）。
> 其中**本方案初稿有 4 处判断被下游规格纠正并撤回**（T2 / T7 / T8 / T9 / T11），
> 另有**文案精简规格的激进部分被驳回**（改引导文案、删按钮、改 `main.js`）。
> **本轮仍只交付方案，未改任何源码、未重新部署。**

## 2. 现状诊断（基于 `index.html` / `style.css` / `ui.js` 实测 + 对局截图 `.tooling/live/E1_board.png`）

### 2.1 量化

| 指标 | 现状 | 问题 |
| --- | --- | --- |
| 字号档位 | 9 / 9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 14 / 15 px，**11 档** | 无主次，视觉上全是「小字」 |
| ≤11px 文本占比 | 约 **70%**（全表 38 处中 27 处） | 桌面与移动端都吃力 |
| 对局屏可见信息单元 | 约 **60+**（顶栏 10、左栏 12、中栏 34、右栏 6） | 首屏无落眼点 |
| 客人卡 | 3 张 × 8 项 = 24 项 | 9 条 9.5px 状态条挤在卡片底部 |
| 话头卡 | 5 张 × 4 层 = 20 项 | 与「添茶 / 指认」同尺寸同色 |
| 移动端热区 | `.topic-card{padding:6px 2px}`、`.tone{padding:3px 7px}` | 明显低于 44×44 触控下限 |
| 可见说明文字 | 约 **2900–3250 字**（文案规格 §6 统计） | 玩家 30 秒内读不完才能问第一句 |

### 2.2 结构问题（截图证据）

1. **三栏等权**：`grid-template-columns: 220–270 / 430–1fr / 240–300`，三栏同为 `.panel` 同描边同阴影，无一栏是主视线。
2. **中栏四段争高**：`.section-hint` + `.guest-row` + `.dialogue-wrap(flex:1)` + `.action-dock` 纵向堆叠，720px 高视口下对话区被压到约 170px，操作台却占 150px。
3. **右栏默认常驻**：AI 决策轨迹未问话时是 6 行说明，占 1/4 屏宽。
4. **操作台内部分三层**：`dock-head` / `topic-row` / `dock-foot` 每层都在争夺注意力。
5. **终局动作无权重**：「点灯 · 指认无相」是 `btn-small btn-danger`，与「添茶 · 缓一口气」同级。

## 3. 目标信息架构：三层

| 层 | 内容 | 视觉待遇 | 默认态 |
| --- | --- | --- | --- |
| **L1 决策层** | 剩余灯数、夜次、当前选中客人、5 张话头卡（名称 + hint）、3 种语气（名称 + desc）、物证真值、指认入口 | 18–20px / 琥珀高对比 / ≥44px 热区 / 唯一暖色实心 | 常驻、最亮、不可折叠 |
| **L2 证据层** | 柜上物证、证词簿、灯下对话、结算真相与复盘 | 13px / 常规正文色 / 细描边面板 | 常驻、中性、区域内部滚动 |
| **L3 辅助层** | AI 决策轨迹、solver-note、seed、键盘串、赛事眉标、工程自检 | 11–12px / 灰阶 / 弱描边 | 降权或换行，**不隐藏取证信息** |

一句话：**把「工程自豪感」从首屏移到弹窗里，把屏幕让给这一句要问谁、问什么。**
硬约束（文案规格 W1–W8）：余灯、夜次、四档档名、话题↔物证真值、AI 决策理由、证词簿、seed、证据链/得分**一律不折叠、不隐藏**。
