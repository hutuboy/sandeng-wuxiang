**关键推论三：官方对 AI NPC 有一条硬指标。**
> 「AI NPC 可结合角色记忆与游戏状态自主决策，通过可校验的实际行动影响游戏进程，**仅实现对话功能的 NPC 无法满足评奖要求**。」

这条是本作的设计依据，而且**本作完全满足，且比大多数"接一个聊天 API"的作品更彻底**：客人会拒答、会离店、会遁走，每一次都真实关掉一条证据路径。这是被严重低估的强项（详见 §3.1）。

## 2. DGX Spark 算力支持计划：它其实是一张"AI 原生性"体检表

官方规定（来源：赛事长图 + 赞奇科技公众号）：

| 项 | 内容 |
|---|---|
| 面向对象 | **AI 游戏、AI NPC 及游戏工具 / Agent 创作者** |
| 审核方式 | 完成报名后**审核项目匹配度**，通过后由工作人员联系开通 |
| 资源池 | 赞奇科技 DGX Spark 云节点 **50 台** + 华硕 DGX Spark 云节点 **15 台** |
| 倾斜规则 | **华硕节点优先支持 AI NPC 团队** |
| 发放方式 | **先到先审，发完为止**；未获得不影响参赛 |

硬件事实（NVIDIA 官方）：GB10 Grace Blackwell，**128 GB 统一内存**，1 PFLOPS FP4，可推理 **200B** 参数模型 / 微调 **70B** 参数模型，内存带宽 273 GB/s。

**核心判断：** 官方在用"你要不要算力"反向筛选"你是不是真在做 AI"。
一个完全不产生推理负载的项目，在"项目匹配度"这一栏天然接近 0 分。这不是运气问题，是**立项形态问题**。

而当前 `docs/创作手记.md` 第 3 节写的是：

> **赞奇科技 DGX Spark 节点：** 未申请、未使用。本作不需要模型训练或本地大模型推理……
> **华硕 DGX Spark 节点：** 未申请、未使用。同上……

诚实是对的，**但这段表述把自己钉在了"AI 运用低分 + 算力不匹配"的交叉点上**：等于主动向评委声明"我没有 AI 算力需求"。
注意华硕 15 台明确"优先支持 AI NPC 团队"——本作正是 AI NPC 游戏，**赛道完全对口，卡住的只有"匹配度"这一栏**。

## 4. 优化思路：四层，按投入产出比排序

### L0 ｜ 今天就能做（约 2 小时，改叙事顺序，0 技术风险）

1. **完成报名**（算力申请的前置条件，页面写明"完成报名后审核"）。
2. **申请 DGX Spark**（先到先审，已开赛 9 天，越晚越少）。申请理由必须写"算力刚需"，见下。
3. **重写创作手记第 3 节的算力表述**：保留"未使用"的事实，把因果从「不需要」改为「未获配 → 端侧保底 → 若获配将用于三件事」：
   - A. NPC 人设 **LoRA 微调**（三位客人各自语癖，DGX Spark 支持 70B 微调）
   - B. 8B~32B **本地推理**替代云端 API（把 NPC 首句延迟压到 800ms 内）
   - C. **规模化自动对局评估**：用 LLM 当玩家跑 1000 局 × 4 档难度，回归验证"AI 改动没破坏可玩性"
     ← 这一条最能证明算力刚需，且与现有 104 项验收体系天然衔接，不是硬凑。

> 收益：同时改善"AI 运用"观感与"项目匹配度"，成本几乎为零。**这是全案性价比最高的一步。**

### L1 ｜ 可插拔模型层（3~5 天，收益最大）

**架构原则：决策归规则，表达归模型。**

```
玩家动作 → 效用 AI 决策（现有，保持可解释/可复现）
              ↓ 选中动作 + 状态 + 记忆
          LLM 只做两件事：
            ① 把动作渲染成台词（说什么）
            ② 给出"想做什么"的建议（仍必须过 legalMask + 规则校验）
              ↓ 校验失败 / 超时 / 断网
          自动回落模板文案（现有实现），游戏永不阻塞
```

为什么这样切：

- 官方硬指标要的是"**实际行动**影响进程"。让 LLM 只负责措辞，它就无法编造线索、无法破坏案件可解性——**这恰好是推理游戏最怕的事**。
- 反过来，如果让 LLM 直接决定"说不说谎"，幻觉会造出不存在的物证，**可玩性 30 分先崩**。这是红线，不能为了"显得 AI"去踩。
- "神经 + 符号双层"本身就是可以写进手记的工程观点，比"我接了个 API"高一个层次。

**双版本部署（必须）**：

| 版本 | SDK | 定位 | 风险 |
|---|---|---|---|
| static（现状） | `static` | 保底，断网可玩，104 项用例全保留 | 无 |
| 增强版 | `docker`（端口 7860） | 挂模型服务（vLLM / Ollama） | 需阿里云绑定 + 实名认证 |

创空间技术约束（魔搭官方文档）：免费档 `platform/2v-cpu-16g-mem`（2 核 16G，跑不动 7B）；GPU 需申请加入「xGPU 乐园」，可选 `xgpu/8v-cpu-32g-mem-16g`（16G 显存）或 `xgpu/8v-cpu-64g-mem-48g`（48G 显存）。

**验收（新增，不能少）**：模型层降级三连测——断网 / 超时 / 幻觉输出（要求它返回不存在的物证 ID），三种注入下游戏必须仍可完整玩完一局。

### L2 ｜ 把验收体系变成"看得见的资产"（2~3 天）

现状：104 项用例只是脚本和 JSON 报告，评审不会去翻仓库。
动作：游戏内加一个「AI 自测台」入口（复用现有"工程自检报告"弹窗），直接展示：

- 44 项难度验收 + 60 项引导验收的**实时通过数**
- 12 组「档位 × 夜次」参数矩阵
- 8 帧逐帧视觉复核的签名状态
- 影子掌柜自动试玩的通关率对比（**78% → 91.7%，55/60**，这是真实调优数据）

> 收益：直接把"最佳 Agent 工程实践"从"我有脚本"变成"评委当场能点开看"。这是当前最被浪费的资产。

### L3 ｜ 工具化（3 天，可选，冲单项奖）

`director`（约束求解生成可解案件）+ `agent`（自动试玩与不变量检测）已经与渲染层解耦，抽成独立包（如 `sandeng-case-gen` / `sandeng-qatrace`）成本不高。
"最佳 AI 原生游戏创作工具"奖品正是 DGX Spark 1 台——说明官方认为这个方向需要算力，也意味着**参赛者可能最少**。

### L4 ｜ 人气奖（持续，纯运营）

5 个名额，按点赞数取前 5。已有素材齐全（8 帧 + 16 秒视频 + 完整手记），缺的只是分发节奏：小红书 / 公众号 / 即刻，每 2~3 天一条，讲"AI 造游戏"的过程而不是成品广告。

## 6. 取舍与红线

1. **static 版永不降级。** 增强版挂了也要能玩——评审现场断网、额度用尽都是真实风险。
2. **不让 LLM 决定线索真假。** 会让案件不可解，直接击穿可玩性 30 分。
3. **不虚报算力使用。** 一旦被核验出"声称用了但没用"，诚信问题远大于加分。写法是"未使用 + 将用于什么"，不是"已使用"。
4. **20 天内不改核心玩法。** 现在的循环、难度、引导都已验收完毕，动它就是自毁 104 项用例。
5. **算力没批下来的降级路径**：浏览器 WebGPU 小模型（Qwen3-1.7B 级）或"玩家自填 API Key"，都要有模板兜底。

## 7. 需要拍板的三件事

1. **是否已完成报名？** —— 这是算力申请的硬前置，页面写明"完成报名后审核"，且先到先审。
2. **是否接受 docker 架构？** —— 需绑定阿里云账号并实名认证；不接受就只能走"端侧小模型 + 云端兜底"。
