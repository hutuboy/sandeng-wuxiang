## 1. 验收条件与判据总原则

### 1.1 唯一标尺
用户原始需求 = **「优化操作界面（减堆叠 / 删冗余文案 / 强化核心信息与关键操作入口），硬约束是不改变游戏核心功能」**。
因此验收分两问，缺一不可：

- **问一（功能不变性，权重最高）**：核心功能**确实**没变 → §2 + §3；
- **问二（界面确实变友好）**：**可测量**地变好，而不是「设计说变好了」→ §4 + §5。

> 只要问一有一条阻断项 FAIL，无论问二多漂亮，结论一律 **不通过**。

### 1.2 核心方法：A / B 冻结对拍（本轮最重要的一条）

**期望值必须来自独立来源，不得引用被测常量或被测函数。** 落到本场景：

| 禁止 | 允许（唯一） |
| --- | --- |
| 读 B 版 `SANDENG_API.getState()` 自己跟自己比 | **A 版（v1.4.1）实测输出**作为期望值 |
| 读 B 版 `Difficulty` 配置 / `CONFIG` / `PARAM_KEYS` 生成期望 | `tools/qa/difficulty-matrix-oracle.cjs` 顶部写死常量（§12.1 指定恢复源）与 `docs/难度分级-设计案-v1.md` |
| 读 `js/game.js` 的计分公式当「期望」 | `docs/交付清单.md §七·五` + 设计案 §5.3 记录的公式，配合 A 版实测 `chain / lampsLeft / avgTrust` 手算 |
| 用 `deepEqual` 判「快照相同」 | `JSON.stringify` **序列化字节**逐位比对（含字段顺序），`Buffer.equals` + `sha256` |
| 用「改后跑一遍门禁看 exit 0」代替对拍 | 对拍 + 门禁双轨；门禁证明「没崩」，对拍证明「没变」 |

**基线 A 的取得（改后验收时执行，本轮不执行）**：
```bash
git -C "D:/Projects/games/AI造游戏" worktree add /tmp/sandeng-v141 v1.4.1
# 或只读导出：git archive v1.4.1 | tar -x -C /tmp/sandeng-v141
```
A 与 B 各用**互不共享 localStorage 的独立 browser context**，同源 `file://` 地址、同 viewport、同 `?guide=0`、L2 云端兜底默认关。

**复现主键**：`(seed, night, tier)` —— 取自 `tools/qa/difficulty-contract.cjs` 的 `REPRO_KEY`，**不新写一份**。
URL 入口必须是玩家可用的 `?seed=X&night=N&difficulty=T&guide=0`（**非 `SANDENG_API` 调试钩子**）。

**测试矩阵**：3 seeds（`QA-DIFF-A/B/C`，复用既有 seedPool）× 5 档（4 个 tier + 1 个「不带 `?difficulty`」默认档）× 3 夜 = **45 组**。每组采：
- `S0` 冷启动快照（未派发任何动作）
- `S1…Sn` 固定动作序列逐步快照（动作序列写死在判据附件，A/B 共用同一份，不读实现生成）
- `Send` 结算快照（`phase=ended`）
