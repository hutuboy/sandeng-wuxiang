## 1. 验收条件与判据总原则

### 1.1 唯一标尺
用户原始需求 = **「优化操作界面（减堆叠 / 删冗余文案 / 强化核心信息与关键操作入口），硬约束是不改变游戏核心功能」**。
因此验收分两问，缺一不可：

- **问一（功能不变性，权重最高）**：核心功能**确实**没变 → §2 + §3；
- **问二（界面确实变友好）**：**可测量**地变好，而不是「设计说变好了」→ §4 + §5。

> 只要问一有一条阻断项 FAIL，无论问二多漂亮，结论一律 **不通过**。

### 1.2 核心方法：A / B 冻结对拍（本轮最重要的一条）

**期望值必须来自独立来源，不得引用被测常量或被测函数。** 落到本场景：

| 禁止 | 允许（唯一） |
| --- | --- |
| 读 B 版 `SANDENG_API.getState()` 自己跟自己比 | **A 版（v1.4.1）实测输出**作为期望值 |
| 读 B 版 `Difficulty` 配置 / `CONFIG` / `PARAM_KEYS` 生成期望 | `tools/qa/difficulty-matrix-oracle.cjs` 顶部写死常量（§12.1 指定恢复源）与 `docs/难度分级-设计案-v1.md` |
| 读 `js/game.js` 的计分公式当「期望」 | `docs/交付清单.md §七·五` + 设计案 §5.3 记录的公式，配合 A 版实测 `chain / lampsLeft / avgTrust` 手算 |
| 用 `deepEqual` 判「快照相同」 | `JSON.stringify` **序列化字节**逐位比对（含字段顺序），`Buffer.equals` + `sha256` |
| 用「改后跑一遍门禁看 exit 0」代替对拍 | 对拍 + 门禁双轨；门禁证明「没崩」，对拍证明「没变」 |

**复现主键**：`(seed, night, tier)` —— 取自 `tools/qa/difficulty-contract.cjs` 的 `REPRO_KEY`，**不新写一份**。
URL 入口必须是玩家可用的 `?seed=X&night=N&difficulty=T&guide=0`（**非 `SANDENG_API` 调试钩子**）。

### F.5 8 帧视觉复核协议 v1.1（Y07）★★★★★

**先记录门禁的真实机制**（本版实读 `tools/difficulty-smoke.cjs` L886–923，不是从文档抄的）：
- 逐帧判据 = `sigMatched`（`JSON.stringify(rec.sig) === JSON.stringify(s.sig)`，**键序敏感**）+ `bytesInBand`（`s.bytes / rec.bytes ∈ [0.7, 1.4]`）+ `rec.pass === true` + `rec.reviewer` 非空
- 像素 `sha256` **记录但不作门禁**（注释：连跑两次 8/8 帧哈希不同）
- **已发现的门禁漏洞（v1.1 必须补掉）**：`visualReviewPass = detail.length >= 5 && every(...)` —— **只要求 ≥5 帧**。少采 3 帧仍能 `true`。→ Y07 断言写死 `frames.length === 8`。

**Y07 断言**

1. `report.screenshots.length === 8`（**写死 8，不接受 ≥5**），8/8 帧 `sigMatched && bytesInBand && pass && reviewer` 全真；**且这 8 张 PNG 必须是本轮 `difficulty-smoke` 自己采的**（核 `mtime` 晚于改动时间 + `git status` 里 `docs/screenshots/difficulty-*.png` 为 `M`）——图是被谁覆盖的说不清，就不能当复核证据
2. `sig` 五键齐备 `{screen, tier, lamp, picked, size}`，`lamp` 严格 `N / N 盏`
3. `docs/screenshots/difficulty-visual-review.json` 的 `frames` 条数 = 8 且每帧字段齐备（见下表）；`notHumanPlaytest: true` 保留不改写
4. **双复核人，缺一不可，且不得互相顶替**：
   - **复核人 A（帧级）= 制作人 AI 目视**，逐帧 8/8；每帧 `note` **≥40 字**，须写出「看到了什么」（如「顶栏 6 / 6 盏、三客人卡无挤压、话题五卡完整、指认按钮居最右」）。**只写 `pass` 或「正常」判无效。**
   - **复核人 B（真人）= 用户本人**，走独立字段 `humanPath{recorded, watchedBy, watchedAt, hooksUsed}` + `humanPlaythroughPass`；H01 原样有效。
   - `visualReviewedBy[]` 是 **A 的签名池**，**不得**当作「已有人真人试玩」的证据。
5. **`bytes` 重采纪律**：**不得沿用旧 `rec.bytes`**。`0.7~1.4` 是「同样输入」的带宽，不是「跨版本仍成立」的带宽。每批改动都必须「重采 → 逐帧目视 → 重签 bytes」。
6. **`sig` 变化判读表（v1.1 新增的判断力）**

| 现象 | 判读 | 处置 |
| --- | --- | --- |
| `sig` 全等、`bytes` 越带 | 正常（文案/样式改了，状态没改） | 重采 + 重签 bytes；越带本身**不算缺陷** |
| `sig` 只有 `size`/`lamp` 因规格要求变 | 需逐帧书面说明 | 未说明 → 阻断 |
| `sig` 的 `tier` / `picked` / `screen` 变化 | **状态被改了** | **阻断**（F02–F04 应已拦住，此处是第二道） |
| `frames.length != 8` | 采集漏帧 | 阻断（漏洞见上） |

7. **复核记录字段表**（v1.1 追加 3 个字段；`loadVisualReview()` 只读 6 个键，**追加字段不破坏门禁**）

| 字段 | 谁填 | 要求 |
| --- | --- | --- |
| `frame` / `pass` / `reviewer` / `note` / `sig` / `bytes` / `sha256` | A | 既有 7 键，`note ≥40 字` |
| **`reviewKind`**（新） | A / B | `ai-frame` \| `human-playtest`，两者**不得**都填 `ai-frame` 却声称真人已看 |
| **`bytesRatio`**（新） | A | 复核当时实测比值，要求 `1.000` |
| **`viewedAt`**（新） | A | 复核时间（ISO8601），须晚于当批改动时间 |

> **两种「8 帧假绿」**：① 截图存在 ≠ 复核过（`reviewed:true` 但 `note` 为空 → 按未复核计）；② 复核人签了名但没打开图（`note` 写的是规格里的形容词而非画面内容 → 按未复核计）。
