## 二、系统实现方案（分层实施结构）

**职责**：把美术/创意规格落到**展示层**，同时保证核心逻辑零改动、DOM 契约零破坏、既有验收可复跑。界面优化不是新系统，是一次「带契约约束的重排」。

**数据结构**：
- 唯一事实源 = 本单第四章 DOM 契约表（39 条 R 级 + 3 行 O 级 + 6 类可改区归纳），任何改动先在表里查编号。
- `SD.UI.paint(ctx)` 的 `_cache` 以 **id 字符串为键**，故 id 是缓存主键，不可改名。
- `window.SANDENG_APP`（`screen / game / selected / tone / session / autopilot / aiShown…`）与 `window.SANDENG_API` 的形状是线上脚本的数据通道（`verify_live2.cjs` 读 `SANDENG_APP.game.cs.clues[].used / phase`）。
- 两个存储键：`sandeng.save.v2`（存档）、`sandeng.guide.v1`（引导标记）；本轮不碰。

**关键流程**：改动 → 本地四套门禁 → 8 帧视觉复核（重采 + 人工签 reviewer）→ 14 文件推 master + `POST /deploy` → `status=Running` → 线上端到端 + 复盘卡复验 → 记录新 HEAD。失败 → `git checkout v1.4.1 -- <本阶段文件>` → 只恢复、不夹带改进 → 改进另开一单。

**对外接口（签名与返回结构一律不得变）**：
- `SD.UI`：`esc / markWords / portrait / initCanvas / audio / showScreen / openModal / closeModal / toast / paint / paintResult / resultHtml / resetCache / KEY_HINT`
- `SD.Guide`：`KEY / TOTAL / status / start / maybeAutoStart / forceCleanup / finish / copyOf`

## 八、技术债与风险

1. **C-6 历史裁决冲突**：`docs/引导-制作人裁决单-v1.md` C-6 规定 `assets/style.css`「只追加段落、不改任何既有规则」。「减堆叠」若直接改既有规则会打破该约定 → P0 用末尾追加覆盖段规避；若 P1 确需改既有规则，**须先请制作人 / QA 会签升版裁决单，不得静默改**。
