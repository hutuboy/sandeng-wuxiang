## 四、判据四条 · 逐条落地（写断言前必过）

### ① 独立复算（期望值不来自被测常量 / 被测函数 / DOM）

- **唯一来源**：`docs/难度分级-设计案-v1.md` 的「参数终值表」。脚本顶部常量形如
  `const EXPECT = { TIER: { ... }, DEFAULT_TIER: 'TBD', LEGACY_FALLBACK_TIER: 'TBD', NIGHT_BASE: {...}, COMBINE: 'TBD', MIN_ACTIONS: 3 };`，
  **逐字抄录规格表**并在报告写 `specSource` / `specSnapshotHash` 证明来源。
- **禁止**：`require('js/director.js')` 取 `difficulty()`、读取 `game.cs.difficulty`、`copyOf(实现常量)`、把页面首次显示的档位参数抄下来当期望值、用 `SANDENG_API` 的返回值反推期望值。
- **观测通道 ≠ 期望值**：三通道（DOM 文本 / DOM 元素计数 / `getState()` 契约字段）只用于取**实际值**；期望值一律来自顶部常量。
- **附录 B 的夜次基线表是「静态源码事实」，不是判定期望值**，不得拷进脚本当常量（见采信矩阵 M-09）。
- `MIN_ACTIONS = 3` 为**手算**：每夜 3 位客人，理想玩家至少问遍三人 → 至少 3 盏灯；与 `Director.solve()` 里 `cost = cs.guests.length` 无关。

### ⚠️ 本轮自纠留痕（不许抹掉）

- **首跑 `FAIL`，17/20**：H3 三条样本全错 —— `actual={"lamps":4,"clueCount":3,"temperature":3}`（期望 `clueCount:2, temperature:1`）。
- **根因**：`combineParams` 把「灯数下限 `min=3`」当成**全局** min/max 套到所有字段，`clueCount`/`temperature` 被错误抬到 3。这是「事实为真、归因错配」的同型错误：加法本身没错，错在 clamp 的适用范围。

- **纪律结论**：若跳过自验直接拿 H3 当判定依据，会把参数被污染的实现判成 PASS。这与团队历史三次自纠同源。

> 自测样本构造不出来的工具**只能当线索，不许当判定依据**。H3 即属此类：算术骨架可自测，但 `EXPECT.COMBINE` 未落盘 → 契约公式正确性未覆盖。

## 九、真人玩家试玩：独立门禁（AC-12，**不得用 AI 视觉复核顶替**）

- **独立通道**：与全部自动化断言分开，单独一条门禁、单独一组截图 / 录屏、单独报告字段。
- **路径（硬性）**：关掉一切 → 浏览器地址栏直接打开 `index.html` → 不点文件、不看 README、不用任何调试钩子 → **从冷启动、不做任何额外操作**走到第一个决策点（选档 → 点灯开局 → 第一个话头）。`hooksUsed = 0`。
- **如实标注**：`humanPending: true`、`humanPlaythroughPass: false`。`visualReviewPass` / `visualReviewedBy` 属于 **AI 视觉复核**，只能证明「帧渲染出来了」，**证明不了有人玩过、更证明不了顺手**。
- **结论规则**：只要报告里没有真人试玩记录，就必须在结论中显式写出「**只有自动化结果，没有人玩过**」；不得以 19 帧视觉复核、60/60 用例、零报错等任何自动化结果推出「可交付 / 能玩」。
- **三条手感判据映射**（缺一不可，必须在能玩的东西上发现）：

| 判据 | 难度分级里测什么 | 合格判据 |
| --- | --- | --- |
| 操作响应 | 点档位卡 → 选中态 / 参数面板更新是否跟手 | 可复跑：响应帧数采集（阈值未声明 → 未覆盖）**＋ 真人试玩录屏**判「顺不顺手」 |
| 消除时机 | 切档 / 非法 id 回落 / 局内拒绝后，旧档参数与临时层是否在该消失时消失 | 可复跑：动作后 N 帧 `residualTierStateCount = 0`（D-35） |
| 穿模 | 局内改档是否走了不该走的路 | 可复跑：非法路径被拒绝，且**被拒绝时状态逐位不变**（D-34） |

## E.3 12 组极值独立复算（判据④，实际跑一遍，不抽样）

工具：`node tools/qa/difficulty-matrix-oracle.cjs`（独立可跑、无外部依赖、不写文件）。

**判定工具先自验**：6 个已知答案样本（**3 命中 + 3 不命中**）→ **6/6 PASS**；命中样本含上界极值、默认档恒等性、下界极值；不命中样本含「同夜不同档必须不等」「非法 id `easy` 必须被拒绝」「非法夜次 0 必须被拒绝」。抽 3 个真实命中回原文人工复核，原文出处 = 设计案 §5.3 派生终值表。

**复跑原始输出（摘要）**：

```
=== difficulty-matrix-oracle PASS ===
harnessSelftest 6/6 (命中 3 / 不命中 3) qualified=true
matrix 12/12 与 §5.3 派生表逐项一致
boundary 12/12 合法区间 + lamps>=3 + endingBestChain=3*clueCount 全成立
extremes upper=novice|1 lamps:8 / lower=advanced|3 lamps:3 / basicIdentity=[true,true,true]
matrix_oracle_exit=0
```

- **独立复算**：`derive()` 是 §5.2 公式的独立实现；期望值来自 §5.3 派生表（写死常量）。两个独立来源互证 → **12/12 一致**，说明设计案公式与派生表自洽，未发现「事实真·归因错配」。
- **取2 浮点自洽性**：另跑 `node -e` 验证 `Math.round(x*100)/100`，`1.15×0.90 → 1.03`、`1.15×1.10 → 1.26`，与 §5.3 表一致（JS 浮点使 `.5` 略向下），**设计案 L264 的「取2」定义与派生表无矛盾**。
- **可达性**：12 组全部落在 §1.3 合法区间、`lamps ≥ 3`、`endingBestChain = 3×clueCount`；`basic` 三夜逐项 ≡ `D₀`（恒等性成立，回归基线不动摇）。

### ⚠️ 第二次自纠留痕

- **首跑 `FAIL`，自验 3/6**，但 `matrix 12/12` / `boundary 12/12` 已通过。
- **根因**：自验样本拿 `derive()` 的**完整输出**（含 §5.2 派生列 `endingBestChain`）去逐位比 §5.3 表（**只有 12 列**），字段集不齐 → 3 个命中样本被误判为 FAIL。`matrix` 段本就按表键集投影，故不受影响。
- **处置**：新增 `project(actual, expect)` 按表键集投影后再比；派生列交由 `boundary` 段单独校验；复跑 6/6 PASS。
