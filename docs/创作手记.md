## 1. 创意与玩法

### 灵感

「剧本杀里的 NPC 太听话了。」——这是起点。玩家问一句，NPC 回一句预设台词；
无论你之前冒犯过他三次，还是刚替他添过茶，他给出的都是同一句话。

我想做的不是「会聊天的 NPC」，而是**会因为你做过什么而改变自己行为的 NPC**：
他记得你问过什么，会掂量值不值得说，信任不够时拒绝把关键物件交给你，
被逼急了会站起来走人——而这一走，就真的关掉了一条证据路径。

于是有了《三更灯 · 无相客栈》：你是掌柜，一夜三客投宿，其中一位是「无相」，
证词与柜上物证对不上。灯只够点六回，天亮前必须把他认出来。

### 核心循环：五步一窗

一夜不是一个挤满控件的大屏，而是**一步步走完的五幕**。每幕只开一扇窗，顶上一条步骤条标出走到第几步；
所有窗走完，结论才出来。

```
① 点灯  客人到齐 · 柜上物证真值摊开 · 几盏灯一清二楚
② 问询  三客自上而下各占一行（立绘左、五维右）→ 点谁问谁 → 选语气（温问/逼问/示物）→ 点话头（来路/时辰/同行/行囊/信物）
          → AI NPC 自主决策（作答/避答/反诘/交付物件/交心/拒答/离店/遁走）
          → 证词入簿 + 状态回写 + 记忆写入
③ 推演  物证 × 客人 的「相符 / 不符」摆成一张表，用 ∧ / ∨ / ¬ / ⊕ 四个逻辑算子筛人
④ 指认  三位并列，点谁就点灯。选错，灯灭人走
⑤ 结案  真相摊开 + 复盘卡（漏掉的物证 / 自相矛盾 / 离最高结局还差几条证据）
```

**灯**是唯一的硬资源：每次问话消耗一盏，灯尽自动结算。
**语气**是策略维度：温问养信任（可触发「交心透底」额外证词），
逼问容易拿到直答但推高张力，示物压伪饰却会累积疑心——第三夜疑心过高，无相会直接遁走。
**证词簿**保留原话，值被高亮；「摊开比对」把物证真值与已收录证词并排摆好，判断留给玩家。

### 推演台：把「推理」真的做成逻辑

旧版判定是「谁与物证不符的次数最多」——那是**匹配**，不是推理，也让分级只停留在「多两条物证、少一盏灯」。
现在把「某客在{话题}上的说法 ≠ 物证真值」写成原子命题 `A_<topic>`（命题本身就是一次 `¬`），
四个算子都能在推演台上点：

| 算子 | 含义 | 在局里的作用 |
| --- | --- | --- |
| `∧` 与 | 每条都对不上 | 新手档的残卷式：无相两处都错，而清白客只「记岔一条」 |
| `∨` 或 | 只要一条对不上 | 初级档：无相只错一处，其余人一处也不错 |
| `¬` 非 | 并非全部对不上 | 中级档：把「全都对不上」这条路的两个人一起排除掉 |
| `⊕` 异或 | 恰好只有一条对不上 | 高级档：从「全错」与「全对」之间把只错一处的人挑出来 |

**关键改动（v1.7.4）：式子由出题器给，不是玩家猜。**
每档开局，推演台顶上都有一张「当夜残卷」，写明这一局的式子，例如 `⊕(信物 , 时辰)`。
出题器不是随机撞出「唯一解」，而是**反推每个人的说法去满足这条式子**：

| 档位 | 无相 | 诱饵甲 | 诱饵乙 | 换错算子会怎样 |
| --- | --- | --- | --- | --- |
| 新手 `∧` | 两处都错 | 只错一处 | 全对 | 用 `∨` 会把诱饵甲一起网进来（命中两人） |
| 初级 `∨` | 只错一处 | 全对 | 全对 | 用 `∧` 无人命中 |
| 中级 `¬` | 只错一处 | 两处都错 | 两处都错 | 用 `∧` 会把两位「两处都记岔」的清白客一起指成无相 |
| 高级 `⊕` | 恰错一处 | 两处都错 | 全对 | 用 `∧`／`∨`／`¬` 都落在别人身上 |

于是四个档位的差别是**式子结构**，而不是同一道题换皮——「换错算子就筛不出他」这件事，是被 `selftest` 的 T8 逐档断言的。
玩家换算子时，推演台会立刻给一句提醒：「式子变了，筛出来的人也会变」。

**「?」不是「否」。** 有格子没问时，式子落在未定上，结论行会直说「还判不了 —— 三位客人还有格子空着」，
而不是笼统地报「无人命中」。指认屏上的「嫌疑度」也不是数叉，而是**后验**：
未问到的格子按五五开枚举成若干世界，看他在多少种可能里符合残卷式（`Logic.posterior`）。

**灯与信息量**：一盏灯只换一条证词，而式子要吃「两处 × 三人 = 六格」。
新手/初级档的 6~8 盏灯刚够，通关率 96%/95%；中级/高级档只有 4~5 盏、3~4 盏，问不全，通关率贴着随机线。
这是本轮**量出来**的设计缺口（详见 `docs/优化方案-逻辑层与分步窗口-v1.md` §9.8），
修法要么加「对簿」（1 盏灯换三人同答 = 3 格），要么调灯数，都还没动。

### 作品亮点

1. **AI 不是皮肤，是规则本身。** 三个 AI 分工：AI 导演生成案件、AI NPC 决定信息如何流出、影子掌柜自动试玩。没有 AI 决策引擎，这一局根本跑不起来。
2. **NPC 的行为可校验。** 每轮决策在右侧「AI 决策轨迹」里完整摊开：特征向量 → 九个动作的效用打分 → 规则掩码（哪些动作被锁、为什么）→ 实际选中动作 → 状态回写 → 记忆条目。评委不需要读代码就能验证「行为决策可校验」。
3. **状态变化后的重新决策。** 面板一键对比：对信任 −30 / 张力 +30 后，NPC 的合法动作集与行为概率分布如何重算（200 组种子实测平均 L1 距离 0.5436）。
4. **逻辑可推演，不只是可对答案。** 判定从「计数找最不符的人」升级为布尔逻辑定位：`js/logic.js` 把证词偏差写成原子命题，`∧ / ∨ / ¬ / ⊕` 四算子由玩家自己选，推演台把整张「物证 × 客人」表摊开。这是分级之外的第二条深度轴——玩家不是在猜，而是在推。
5. **可复现。** 每一夜由 `seed` 决定；`?seed=xxx&night=2` 可重开同一局，自动试玩输出含初始状态与完整动作序列的轨迹。
5. **差异化结局。** 灯下留名 / 破晓 / 一灯独明 / 空盏 / 灯灭，取决于证据链完整度、平均信任与是否有人离店；三夜通关另有「守夜人 / 掌灯人 / 值夜人 / 夜行人」评级。
6. **零依赖、可离线、100% 原创。** 立绘、夜景、纹理、音效全部代码生成，未用一张外部图片、一个字体文件或一段音频素材。

### 关键设计决定

- **把逻辑层与界面层彻底分开。** `game.js` 不碰 DOM，Node 里能直接跑完整局——这让「自动试玩 Agent」和「跨 200 组种子的不变量自检」成为可能，而不是事后补的演示动画。
- **Static 优先。** 大赛创空间的 Static 类型不支持服务端。既然不能放密钥、不能存服务端状态，就把 AI 推理全部做成端侧可解释模型：零网络、零密钥、零冷启动，离线双击 `index.html` 就能玩。
- **可解释优于「黑箱大模型」。** 评委要看的是「状态可量化、决策可校验」，线性效用 + softmax + 规则掩码恰好能把每个判断摊开给人看，且完全可复现。

## 4. 问题与解决

### 问题一（核心）：重复提问可以刷出额外证词 —— 预置缺陷 F-01

**现象。** 早期版本里，NPC 的 `memory[]` 只用于显示，没有进入决策特征。玩家对同一位客人反复问同一个话题，
每次都可能触发「交心透底」，白拿一条关键话题证词。六盏灯里只要两盏就能凑齐证据链，
推理过程被完全绕过，案件难度归零。

**定位。** `features()` 里没有 `repeated` 特征，`legalMask()` 也没有针对重复话题的约束；
`softmax` 因此反复把 `CONFIDE` 排在前列。

**修复。**

1. `features()` 增加 `repeated`（该客人是否已被问过同一话题），并让 `EVADE` 权重 +1.35、`ANSWER_TRUE` −0.55；
2. `legalMask()` 增加规则：`repeated → 锁定 CONFIDE`，并写入 `ruleNotes` 供面板展示；
3. 语言生成层加入记忆引用句（「这题你方才问过一回了」），让玩家能感知记忆存在。

**前后对比（seed `DEFECT_F01`，动作序列 `[ASK(g0, 关键话题, 温问), ASK(g0, 关键话题, 温问)]`）：**

| | 旧版（关闭记忆写入） | 修复后 |
| --- | --- | --- |
| `repeated` 特征 | 0 | 1 |
| `CONFIDE` 是否合法 | 是 → 可重复发放证词 | 否 → 分支锁定 |
| 第二问措辞 | 无记忆引用 | 引用历史答复 |
| 证据链 | 可被单话题刷满 | 必须换话题或换客人 |

复现脚本 `Agent.defectDemo('DEFECT_F01')` 会同时输出初始状态、随机种子、完整动作序列与两版对比，
浏览器「工程自检报告」弹窗里也能直接看到。

### 问题二：影子掌柜把灯全耗在同一个问话上

**现象。** 首版自动试玩 Agent 通关率只有 78%：Agent 按信息增益排序后，
若某位客人连续「避答」，该问话的覆盖数仍为 0、增益不变，于是 Agent 会一直重复点它，把六盏灯烧光。

**修复。** 从 `game.decisions[].playerAction` 统计每个 `(客人, 话题)` 的尝试次数，
在信息增益里减去 `1.6 × 尝试次数`；第三夜统一改用「温问」以规避「示物」累积疑心触发无相遁走。

**效果。** 60 局自动试玩通关率从 **78% → 91.7%**（55/60），并写入 T6 回归用例长期守护。

### 问题三：中途回封面后「续上昨夜」按钮仍禁用 / 移动端操作台在折叠下方

**现象。** 浏览器冒烟测试发现：按钮的禁用状态只在启动时计算一次，开局后没有刷新；
390px 宽度下操作台需要滚动才能摸到。另外 `file://` 协议下 `localStorage` 可能不可用。

**修复。** 增加 `refreshContinue()` 在每次 `save()` 后同步按钮状态；`continueRun()` 增加内存态兜底
（存档不可写时直接恢复当前局）；移动端把操作台改为 `position:fixed` 吸底并给滚动区留出 132px 内边距。

**效果。** 桌面 / 移动端两轮真实浏览器测试控制台均为 **0 报错**。

### 附：演示视频时间轴跑偏

第一版录屏按「墙钟时间」触发点击，但浏览器出帧速率不稳定，编码后封面占了 6 秒。
改为**按帧号驱动动作**（`waitFrame(f)` → 执行点击），400 帧 / 25fps 精确对应 16 秒，
第 6 秒是对局与 AI 决策面板、第 14 秒是结算页，抽帧复核通过。

## 5. 经验总结

**可复用的经验**

1. **先把评分表拆成功能清单再动工。** 官网写「AI NPC 可结合角色记忆与游戏状态自主决策，通过可校验的实际行动影响游戏进程，仅实现对话功能的 NPC 无法满足评奖要求」——这句话直接决定了架构必须要有「规则层 + 状态回写」，而不是接一个聊天 API。
2. **让 AI 可被看见。** 「AI 决策轨迹」面板是本次最值得的设计：把特征、效用、掩码、状态增量全部实时摊开，既满足评审的验证需求，也成了玩家理解 NPC 脾气的玩法信息。做 AI 原生游戏，可解释性本身就是内容。
3. **逻辑层与 DOM 解耦，换来的不只是可测性。** 因为 `game.js` 是纯状态机，自动试玩 Agent、200 组种子自检、缺陷复现、对外结构化 API 几乎是同一套代码的副产品。
4. **Static 部署的约束反而是优势。** 不能放密钥 → 逼出端侧推理 → 换来离线可玩、零冷启动、逐位可复现，评审现场不会因为网络或额度翻车。
5. **录屏要用帧号而不是秒数驱动。** 浏览器出帧速率会波动，按帧号排镜头才能得到稳定的成片。

**后续想改进的方向**

- 「可插拔云端增强」（已实现为 `js/llm.js` 可选模块，**默认关闭**）：玩家可自愿注入自己的推理服务端点，让 NPC 措辞由大模型润色；端侧引擎始终为离线兜底，超时 1.5s 静默回退，不碰决策与存档，绝不影响可玩性（见 `docs/AI架构-B方案-端侧+云端兜底-v1.md`）。
- 扩充案件类型：多无相、伪物证、NPC 之间互相串供，让「关系值」不只影响单个 NPC。
- 把 AI 导演与自动试玩 Agent 抽成独立开源工具包，供其他创作者复用到自己的游戏里（对应「最佳 AI 原生游戏创作工具」方向）。
- 补一份可分享的「案件种子卡」，玩家能把有意思的一局一键发给朋友复现。
