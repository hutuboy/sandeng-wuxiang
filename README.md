# 三更灯 · 无相客栈

> 一夜三客，一人为「无相」。灯不认人，只认破绽。

一款 **AI 原生网页推理游戏**。三位客人不是写好的剧本，而是由本地 AI 决策引擎驱动的 NPC：
带量化状态、持久记忆、规则校验，会记住你说过的每句话，会因为你逼得太紧而拂袖离店。

**AI+∞ 开发者创作大赛 · 第三期「AI 造游戏」参赛作品**　|　纯静态 · 离线可玩 · 零外部素材 · MIT 开源

**开源仓库**：https://github.com/hutuboy/sandeng-wuxiang

## 五步一窗：点灯 → 问询 → 推演 → 指认 → 结案

一夜不是一个挤满控件的大屏，而是**一步步走完的五幕**。每幕只开一扇窗，顶上一条步骤条标出走到第几步（第①幕是一张开夜卡，不占窗口）。

| 幕 | 你要做的事 | 窗里有什么 |
| --- | --- | --- |
| **① 点灯** | 认人、清点物证 | **开夜那张卡**：夜名、三位客人、柜上物证的应为值、今夜的破绽 —— 一屏交代完，关掉直接进问询（幕条仍留五步，① 作为已过） |
| **② 问询** | 点谁问谁 | 三位客人**自上而下排成三行**，每人一行：**立绘在左、信任/好感/张力/疑心/定力在右**（宽屏五维一行铺开、窄屏两列），点任意一位即换人，没有页签；下面是**精简物证带**（一行一件，点开看全文）压在「灯下对话」之上；选语气、点话头，问一句灭一盏灯。灯不够用时，可以对物证**「对簿」**：同样一盏灯，三人同时开口，一次最多换三格 |
| **③ 推演** | 把表摊开 | 「物证 × 客人」的相符 / 不符表 + 每人「不符处数」；当夜残卷只给**破绽性质**（式子不给），怎么筛是你的事 |
| **④ 指认** | 点头认人 | 三位并列，点谁就点灯。选错，灯灭人走 |
| **⑤ 结案** | 看真相 | 真相摊开 + 复盘卡（漏掉的物证 / 自相矛盾 / 离最高结局差几条证据） |

**逻辑层（`js/logic.js`）** 把「谁的说法与物证不符」写成原子命题，再由 `∧ / ∨ / ¬ / ⊕` 组合成可嵌套的表达式树。
判定不从算子出发，而从**破绽类型**出发——每一档对应一种该找的破绽：

| 档位 | 破绽类型 | 残卷上的性质 | 判定 |
| --- | --- | --- | --- |
| 新手 | `substitute` 有一处对不上 | 有一处对不上，就是「无相」 | `∨` 至少一处不符 |
| 初级 | `cumulative` 处处都对不上 | 处处都对不上，就是「无相」 | `∧` 两处都不符 |
| 中级 | `negative` 并非处处对不上 | 并非处处对不上，就是「无相」 | `¬` 并非全部不符 |
| 高级 | `quantify` 恰好只错一处 | 恰好只错一处，就是「无相」 | `⊕` 恰好一处 |
| 第三夜叠加 | `drift` 改口 | 同一个人对同一件事前后说辞变了，那条也算数 | 同客同话题两次证词不同 |

`judge()` 把「式子命中」与「改口命中」并起来收口，两边合起来只剩一个人才算定案。
`selftest` 跨四档 × 三夜（720 组）断言「满足当夜判定者恰好一位」（T7），并逐档断言
「换错判定必然指错人 / 筛空 / 命中两人」（T8）、「只有第三夜的无相改口、清白客证词恒等」（T9）。

> 说明：**玩家侧看不到算式。** 残卷只交代「这一夜找什么样的破绽」，四个算子按钮已经撤掉，
> 「按哪条式子筛」属于内部实现。判定依据只在第三幕的推演表里体现——表尾替你数好每人「不符几处」，筛不筛得对是你的判断。
> 详见 `docs/逻辑层重设计-方案-v2.md` §九·二。

**判定句摆在眼睛所在的地方。** 点灯之前会先弹一张**开夜卡**：夜名、三位客人、柜上物证的应为值，
顶上第一行是「今夜「无相」的破绽：并非处处对不上」。它就是原来的第①幕「点灯」——一屏交代完，
关掉直接进问询，不用再看第二遍。同一条话随后常驻在**证词簿置顶**（「✓ 找破绽：并非处处对不上」），
整夜都压在证词上方；那行只报判定句，件数、灯数本来就在顶栏与物证条头上，不再重复。
带 `?seed=` / `?guide=` / `?autopilot=` 参数时不弹这张卡（复现与自动试玩通道，弹层会挡住脚本要点的地方）。

## 三个 AI，各司其职

### 1. AI NPC 决策引擎（`js/npc.js`）

```
量化状态 (信任/好感/张力/疑心/定力) + 人格权重 + 交互特征
   → 线性效用打分 → softmax(T) 采样
   → 规则层 legal mask 校验动作合法性
   → 组合式语言生成（引用记忆）
   → 实际行为落库，改变游戏状态与后续决策
```

- **可量化角色状态**：五维数值，实时显示在客人卡与决策面板。
- **行为决策可校验**：`trust < 35` 锁定「交心透底 / 交付物件」；`tension < 70` 锁定「离店」；非无相不可「虚与委蛇」；第三夜疑心 ≥ 60 才开放「趁夜遁走」。
- **对话输出与行为执行的闭环**：`GIFT / CONFIDE / LEAVE / FLEE` 会真实新增证词、关闭证据路径或提前结束本夜，不只是输出文字。
- **持久记忆**：每轮交互写入 `memory[]`；同一话题重复提问时触发 `repeated` 特征、引用历史答复、并锁定重复交心。
- **状态变化后的重新决策**：`NPC.reDecide()` 对状态施加扰动后重新计算效用分布与合法动作集，面板可一键查看对比。

### 2. AI 导演（`js/director.js`）

带约束求解的程序化案件生成：随机选客人 / 人格 / 无相 / 物证，构造唯一矛盾。
四档各对应一种破绽类型（`js/logic.js` 的 `FLAWS`）：新手「有一处对不上，就是「无相」」、初级「处处都对不上」、中级「并非处处对不上」、高级「恰好只错一处」，
第三夜再叠加一条行为破绽「同一个人对同一件事前后说辞变了，那条也算数」；
生成器**按破绽类型反推**每个人的说法去满足它（`js/director.js` 的 `PATTERNS`），于是「满足判定者恰好一位」是构造出来的，不是重掷撞出来的。
`solve()` 用 `Logic.uniqueFor(cs, cs.logic.expr)` 校验，并核对「矛盾唯一 + 行动点充足」；`Logic.judge()` 再把改口并进来收口。
所有案件由 `seed` 决定，可完整复现。难度随夜次递增（红鲱鱼措辞、双物证、遁走分支）。

### 3. 影子掌柜 · 自动试玩 Agent（`js/agent.js`）

只通过结构化接口 `getState() / listActions() / dispatch()` 驱动游戏，与人走同一套规则。
以信息增益选择问话与对簿、以**后验**做指认（未问到的格子按五五开枚举，看他在多少种世界里符合当夜破绽），
输出「初始状态 + 随机种子 + 完整动作序列 + 信念轨迹」。可用 `run(seed, night, { tierId })` 指定档位跑。
另附跨种子不变量自检与预置缺陷复现：

```bash
node tools/selftest.cjs --seeds 200 --json tools/selftest-report.json
```

200 组种子实测：**10/10** 项通过（含 T7「破绽判定命中唯一」720 组、T8「破绽类型区分度」四档、T9「改口」480 组、T10「对簿」288 组）；
自动试玩分档通关率：新手 98.3% / 初级 100% / 中级 88.3% / 高级 83.3%，最高档离随机线（1/3）50 个百分点。
中/高级档曾经只有 35.0% / 33.3%——那是「一盏灯只换一条证词」的信息缺口，用**对簿**补齐，难度契约一个字没改
（见 `docs/优化方案-逻辑层与分步窗口-v1.md` §9.8–§9.10）。

## AI 架构：端侧保底，**LLM 可选、默认关**

核心决策与措辞**全部在浏览器端完成**（`js/npc.js` 效用打分 + 规则掩码 + 模板措辞，`js/director.js` 程序化生成案件），
**零网络、断网可玩、可复现**。云端大模型是**可选项，默认关闭**：

| 层 | 位置 | 默认 | 说明 |
| --- | --- | --- | --- |
| L0 决策 | 浏览器本地 | **必选** | 五维状态 × 人格权重 → 效用 → softmax → 规则校验 → 状态回写；**永不上云** |
| L1 措辞 | 浏览器本地 | **必选** | 人格词典 + 状态/记忆模板组合 |
| L2 云端润色 | 独立代理（服务端持 Key） | **线上已启用 / 本地与门禁关闭** | 只润色台词表层措辞，**不改决策与存档**；5s 超时或任何异常静默回退原文；**每日 250 次调用上限，到额自动停**（次日 UTC+8 零点恢复） |
| L3 DGX 本地大模型 | DGX Spark | **未启用** | 算力**已申请、待审批**；若获批仅用于离线演示 / 录屏 / 评审现场，不挂公开链接 |

**怎么开 L2**（`js/llm-config.js` 只在 `https:` 下填端点；`file://` 本地开发与四道门禁留空 = 完全零网络）：

```js
// 线上默认已指向自建润色代理；如需临时改端点，在浏览器控制台覆盖即可
window.SANDENG_LLM.endpoint = 'https://your-endpoint/polish';
window.SANDENG_LLM.timeout = 5000;   // 毫秒；代理实测 ~1.2s
// 请求体 { persona, state, action, baseText } → 响应 { text, model, quota }
// 到额时响应 { text: null, reason: 'daily_limit', quota: {...} }，前端静默回退原文
```

代理是零依赖的独立 Docker 服务（`proxy/app.py`），浏览器不接触 API Key；`GET /health` 可查
`daily_limit` 与 `quota:{day,limit,used,remaining,stopped}`。详见 `proxy/README.md`。

适配器实现见 `js/llm.js`，只在 `js/main.js` 的 `afterDispatch` 单点挂钩，**不触碰 `game.js` 状态机**；
开启与否不影响 `getState()` 与所有自检结果。设计取舍与计费规避见 `docs/AI架构-B方案-端侧+云端兜底-v1.md`。

## 结构化接口（评测 / 二次开发）

浏览器控制台可直接使用 `window.SANDENG_API`：

```js
SANDENG_API.getState()          // sandeng.state.v1 结构化快照
SANDENG_API.listActions()       // 当前合法动作全集
SANDENG_API.dispatch({type:'ASK', guestId:'g0', topic:'hour', tone:'warm'})
SANDENG_API.newRun('MY-SEED', 3)
SANDENG_API.trace('MY-SEED', 2)  // 完整自动试玩轨迹
SANDENG_API.selftest(200)
SANDENG_API.defectDemo('DEFECT_F01')
```

核心逻辑层（`core / director / npc / game / agent`）不依赖 DOM，可在 Node 中直接 `require`。
